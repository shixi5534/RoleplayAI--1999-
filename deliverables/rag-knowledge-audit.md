## 六·五、RAGAS 2.0 标准级评估（2026-09-01 新增）

对照 **2026 年最新 RAG 评估标准（RAGAS 2.0）** 新增标准级评估脚本 `scripts/eval_rag_standard.py`：
LLM-as-judge（本地 7B）逐指标打分，与关键词级 `verify_rag.py` 互补。

> 最终数据为 **60 用例 / repeat=3**（下表，2026-09-01 晚修复后全量重跑）。
> 评估集演进：8 → 21 → **60**（达到 RAGAS 建议的 50-100 样本量），
> 含 7 个"知识库无法回答"用例 + 5 个口吻场景用例。

| 指标 | 目标（生产门槛） | 实测 | 达标 |
|---|---|---|---|
| Context Precision（检索去噪） | ≥0.80 | **0.98** | ✅ |
| Context Recall（检索覆盖） | ≥0.75 | **0.88** | ✅ |
| Multi-hop（多跳推理，RAG 2.0 新增） | ≥0.66 | **0.80** | ✅ |
| **Refusal（无法回答时正确拒答）** | ≥0.80 | **1.00** | ✅ |

### ⚠️ 样本量对结论的影响（重要发现）

同一套系统，**8 个精选用例**、**21 个扩充用例**与 **60 个全量用例**测得差异显著：

| 指标 | 8 用例 | 21 用例 | 60 用例 | 差异(8→60) |
|---|---|---|---|---|
| Faithfulness | 0.86（看似"逼近达标"） | 0.66 | **0.71** | **−0.15** |
| Context Precision | 1.00 | 0.97 | **0.98** | −0.02 |

**小样本会显著高估系统表现**（选择偏差：精选用例恰好都是系统擅长的类型）。
RAGAS 官方建议 50-100 样本，当前 60 已达标。**0.71 比 0.86 更接近真实水平**。
注意 21→60 阶段 faithfulness 不降反升（0.66→0.71），是因为扩展后发现了检索缺口（槲寄生/平衡伞）并修复，
修复带来的增益抵消了样本扩大的下探——**扩样本 + 修缺口要一起做，单独扩样本只会看到"变差"**。

> **采样噪声**：7B 生成随机性大，需 `--repeat ≥3`（噪声约 ±0.07）。单次数值不可信。
>
> **指标与用例类型必须适配**（曾产生两类假性低分）：
> - 开放式**口吻场景题**（如"你为什么在这里"）正确条目是"怎么回应"的示例，不含事实词 → 用事实型期望词测 precision/recall 会得到假性 0.00（实测检索其实命中 0.944）。此类标记 `scene=True` 跳过。
> - **无法回答题**用 refusal 衡量，不测 faithfulness（拒答内容短，judge 会把"我不记得了"也当无据声明）。

**RAGAS Faithfulness 应用于角色扮演的固有局限**：该指标假设答案是事实陈述，逐条核对；但角色扮演答案是**带情感的转述**（"就像是一个大家庭""特别的东西"），judge 会把这类概括判为"无据"。**0.66 里估计有 0.05-0.10 是这类误伤**，真实编造率更低。继续压 prompt 追求 0.90 会牺牲角色感，不可取。

### 过程中发现并纠正的一个配置 bug

`.env` 的 `ROLEPLAY_RAG_HYBRID_ALPHA` 注释原为"0=纯 BM25，1=纯向量"，**方向标反**。
代码语义（`vector_store.py`）为 `score = (1-alpha)×稠密向量 + alpha×BM25`，即 **alpha=0 纯向量、alpha=1 纯 BM25**。已纠正注释。

并得到一个反直觉的实测结论：**对"发条装置"这类专有名词精确查询，BM25（alpha→1）反而比向量更准**（向量把语义相近的剧情条目排前）。这提醒"角色扮演就偏向量"不是普适结论——当前 0.45（55%向量）对 5/6 关键查询已是最优，未全局乱调。

### 依据此评估完成的修复

1. **忠实性约束收紧**（`persona_prompt.py`）：旧措辞"资料未覆盖的细节可以合理演绎"实测会诱发幻觉（模型补全心理动机、编造场景，Faithfulness 掉到 0.50）。改为显式边界：**只许演绎口吻/修辞，禁止添加具体事实；资料没提到的宁可留白**。
2. **修辞锚点约束**（`persona_prompt.py`）：比喻/修辞之后必须带出至少一个资料里的具体事实，避免"只剩意象没有信息量"。
3. **事实优先约束**（`persona_prompt.py`）：问"是什么/谁"类事实问题先直接给事实，修辞只能点缀。
4. **采样温度 0.8→0.6**（`.env`）：7B 在 0.8 下倾向放飞（纯修辞、编造对话场景），0.6 保留角色灵动性同时显著抑制。

### 评估脚本的踩坑记录（可复用）

- **7B judge 打 0-1 浮点不可靠**：常输出 0/1 极端值，改为 1-5 整数分 + few-shot + JSON 输出后稳定。
- **max_tokens 太小导致截断误判**：judge 先输出解释时被截断、正则取不到数字 → 全部误判 0，需给足 token。
- **子串匹配严重低估 recall/multihop**：角色口吻用"那个组织"而非"重塑之手"，必须用 LLM 语义判断。
- **judge 会把修辞当事实声明判罚**：明确"只评估事实断言，比喻/反问/情绪不算"。
- **评估必须走生产 prompt 链路**：用自定义简化 prompt 测出的数字不代表生产，需走 `build_roleplay_prompt`。

3. **知识补全**：`核心名词速查.md` 新增"司辰小队"条目（高频问题"谁批准你加入司辰小队"此前检索不稳）；口吻库新增 2 条多跳锚点条目（"阿尔卡纳对我做过什么""谁批准我加入司辰小队"），Multi-hop 0.58→0.67。

### 测量工具踩坑记录（重要）

- **7B 不能做开放式 0-1 浮点评分**（relevance/相关性）：答案完全正确也常判 0 或 1，无判别力。改用**确定性代理**（核心词覆盖）或 1-5 整数分 + JSON 输出。
- **Context Precision 用 LLM 判断不可靠**：3/3 条都相关也全判 0。改用核心词覆盖代理。
- **7B 生成有随机性**：faithfulness 单次采样波动大（0.61-1.00），需多次采样取均值（脚本 `--repeat`）。
- **评估必须走生产链路**：用 `build_roleplay_prompt`（含完整角色卡）而非简化 prompt，否则结果不代表真实水平。
