## 0. 一句话结论

**这层此前"看起来能用、实际不可用"**：单次检索要 7–15 秒（97.6% 耗在一个 O(实体×别名×全语料) 的正则全扫上），三条召回通道分数量纲互不可比导致**图结构（PPR/多跳）这条最有价值的能力从未真正进入过提示词**，而唯一的质量证据（灰机 14 题 93%）来自"非生产配置 + 并集子串命中"的宽松口径——把同一套题放进生产配置与 300 题集后，**严格通过率只有 46%**。

本轮做了四件事：**补齐可复现的评测台**、**把检索从秒级压到 300ms 内（49×）**、**统一三通道排序并引入路径归因**、**加种子门控把离题注入从 36 块清零**。优化后在生产配置上与旧实现**严格通过率持平（46.0%）**、MRR 持平、块精度微降 0.018，换来 **49× 延迟**与 **离题零注入**；性能与门控两项均达标，而 P2 排序的"+10pt 质量增量"假设**未达标**，按预案保留经消融验证的最优配置并如实记录（见 §4、§6）。

## 2. 审查发现

### F1【P0·性能】检索耗时集中在一次 O(实体×别名×全语料) 的全扫
- **现象**：单次 `retrieve()` 0.17–17.4s，随命中实体的别名数线性放大。
- **证据**：`plot_graph.py:_name_counter` 为每个名字造闭包，`_mention_candidates` 对**全部 8358 块**逐块跑正则/子串计数；「维尔汀和圣洛夫基金会是什么关系」一题 4 个目标实体共 128 个名字。
- **影响**：`orchestrator._plot_retrieve` 虽走线程池，但每轮对话都要等它，并发用户互相排队——这是该层无法上线的首要原因。

### F2【P0·排序】三通道分数量纲不可比，图结构证据被实质丢弃
- **现象**：返回列表中提及路 ≈1.10–1.27、边证据路 ≈0.20、词法兜底是 BM25 原始分（30–75）。
- **根因**：旧实现把三者塞进一个列表按原始分排序；`persona_prompt._filter_chunks` 再按 `0.85×组内 top1` 相对门过滤 → **0.2 量级的边证据块被整批丢掉**。
- **影响**：PPR/多跳这套图能力**从未真正进入提示词**；`via` 只有 `plot_graph`/`plot_lexical` 两个值，连"走的是边证据还是提及块"都无法观测。

### F3【P0·排序】提及块同实体各块同分、名次不可复现
- **证据**：`scored` 按原始命中次数排序，但输出分恒为 `base + 0.0`——同一实体的所有块**同分**，并列名次靠插入顺序决定。
- **影响**：排序不可调、不可复现（实测「露西女士是谁」前两名同为 1.2238）。

### F4【P1·精度】种子卫生失控：任何图内词都能当高分种子
- **证据**：`link()` 的精确匹配对实体度/提及数/是否人工锚定一律不加区分；「今天天气怎么样」精确命中泛词实体「天气」（度 1）→ 注入 5 块；「推荐几家附近的餐厅」经词元兜底蹭上 `restaurant`（度 2）。
- **量化**：300 题中 293 题走精确匹配，**只有 7 题落到词元兜底**，而这 7 题的兜底种子全是「找到他发生了什么」这类碎片；离题问句反而几乎全靠该路径。

### F5【P1·数据语义】"人工别名表最高优先"只写在注释里
- **证据**：`bind_alias_table` 注释称"最高归并优先级"，实现却是首注册优先。实测加载时 4 条冲突**全部由抽取实体胜出**（`Noir` 压住人工规范名「菲林士多」、`Amalfitano`/`阿马尔菲塔诺` 压住「阿马尔菲塔诺村」）。

### F6【P2·溯源】重复 chunk hash 让证据可能指向另一支视频
- **证据**：语料有 **130 组重复 hash（262 块）**；`by_hash` 首见优先，而 `plot_graph.py` 只传 `hash`、丢弃了 evidence 里现成的 `doc_id`。

### F7【P2·正确性】CJK 分词把不相邻的字拼成二元组
- **证据**：`zip(cjk, cjk[1:])` 在**扁平化后的字序列**上拼二元组——实测 `tokenize("暴。雨") == ['暴','雨','暴雨']`，制造跨标点/换行的假词元（污染 BM25 与链接兜底）。

### F8【P0·评测基建】300 题没有 runner；既有指标口径过宽
- 300 题集**没有任何打分脚本**；唯一的质量证据是 14 题的并集子串命中，且：(a) 报告用 `--top 10`（≤12 块）而脚本默认 5，(b) 落盘报告不记 `argv`，(c) 图谱占比恒 1.0。
- 更关键：**oracle 天花板**——27/300 题（9%）不存在任何"单块覆盖全部证据组"的语料块，这类题只能靠多块并集命中，不区分就会把"语料缺口"记到检索头上。

### F9【工具缺陷】（均已修）
| 缺陷 | 影响 | 处置 |
|---|---|---|
| `rag_testset_candidates_300.py __main__` 抛 `KeyError: 'hop'` | 自检入口形同虚设 | `.get` 兜底 |
| 三个评测/诊断脚本**手工装配** `PlotGraphRegistry`，只传 4 个参数 | 与生产配置漂移（本轮消融 7 组结果一模一样才发现） | 全部改走 `build_plot_registry` |
| `scripts/test_plot_graph_retrieval.py` 不在 `testpaths` 内 | 端到端检查从未进 CI | 抽出 `tests/test_plot_graph_retrieval_live.py` |
| 灰机报告不记 `argv`/时间 | 数字不可复现 | 补 `argv`/`ran_at`/`path_counts` |
| R13 幻觉监控口径 = "结果文本含 Lucy 即算幻觉" | 把**真实角色露西**（人工别名表锚定、灰机核实）的正常提及误判 | 改为两个可证伪不变式（见 §7） |

## 3. 优化实施

### P1 性能（语义不变，差分测试守住）
| 改动 | 位置 | 效果 |
|---|---|---|
| 词元倒排**前置过滤**：先取"含该名字词元的块"（实测均值 63 块），再跑同一个精确计数器 | `plot_corpus.candidate_hashes` | 24ms → 0.7ms/名字（原型实测 36×，45 个名字逐块 0 不一致） |
| 命中表按名字缓存（FIFO 上限 512） | `plot_graph._name_hits` | 跨查询复用 |
| 实体名字归一表 + 词元表预计算 | `_named_entities` / `_tokens_of` | 消除每查询 14938 次 `norm_name` 与 14k 次 `tokenize` |
| 按 `store.revision` 缓存"过滤后边表 + PPR 邻接 + hop 邻接" | `_graph_view` + `GraphStore.revision` | 每查询 3 次全边扫描 → 0 次 |
| PPR 内层热循环微优化（`.items()`、免建空列表、提取公因子） | `graph_ppr.personalized_pagerank` | 算式与结果逐位一致 |
| 过滤口径收敛为单一来源 `filter_edges` | `graph_ppr` | 消除"邻接里有、边循环里没有"的口径漂移（本轮真踩到过） |

**正确性护栏**：`tests/test_plotrag_optimization.py::TestP1MentionPrefilter` 用**独立复刻的全扫参考实现**做差分（10 个具名 + 30+ 抽样实体名，逐块比对命中次数），另有超集性质、缓存上限、权重口径、图视图失效等用例。

### P2 排序（三通道 RRF 融合 + 路径归因 + 预算修复）
| 改动 | 说明 |
|---|---|
| **RRF 融合**替代原始分混排 | `fused = Σ w_c/(k + rank_c)`，只用名次、免疫量纲；融合后归一到 `[0.6, 1.0]`（高于 `MIN_CONTEXT_SCORE=0.05`，且保留排序含义） |
| **`k` 必须取小值** | `k=60`（RRF 论文默认）时 `1/(60+rank)` 几乎不随名次变化，**通道权重完全压过名次**——实测边证据霸占全部名额（路径占比 87%）、严格通过率 42%；`k=3` 两路才真正交错（回到 46%） |
| **提及块按实体分组输出** | 种子按 PPR 降序 → 邻居，组内按命中分降序；旧实现靠"所有提及块同分 + 稳定排序"隐式形成该顺序，显式实现后严格通过率 +6pt |
| 新增 `meta["path"]` / `meta["paths"]` | `edge`/`mention`/`lexical`，让"图结构到底有没有起作用"第一次可测；`via` 与 `edge`/`edge_score`/`seed_mention` 原字段保持不变（API/前端零改动） |
| **预算修复** | 图路可用满整个返回预算（`top_chunks + lexical_fallback`）。教训：把图路硬压到 `top_chunks` 会让返回块数 4.83 → 2.86、严格通过率 −9pt——并集口径下"少给块"就是"少覆盖" |
| 同一 `doc_id` 软去冗余 | 先按上限去冗余，名额没填满再放宽（实测中性，保留以防同视频刷屏） |

### P3 精度门控（离题零注入）
| 规则 | 依据 |
|---|---|
| 词元兜底种子必须被人工别名表锚定 | 300 题只有 7 题走该路径且种子全是碎片；离题问句几乎全靠它 |
| 非锚定种子命中**世界常识泛词**时丢弃 | `GENERIC_SEED_NAMES`（天气/经济/故事/restaurant…，只收与作品无关的日常词；**不收**圣火/雅典/伦敦/灯塔/钥匙/十字街/滚鳄书店等实测有效种子） |
| 无通过门控的种子 → 整体短路（词法兜底也不启用） | 「剧情层只回答图能认得的问题」 |
| 两个开关均可经 Settings 关闭 | `plot_require_anchored_token_seeds` / `plot_filter_generic_seeds` |

### P4 加载期语义修复（不改数据文件）
| 改动 | 说明 |
|---|---|
| `bind_alias_table(on_conflict="merge")` | 人工表冲突时**改指**人工规范实体（原持有者保留其余名字），新增 `alias_reassigned` 计数；**默认 `skip` 保持既有语义**（lore 层与 `test_alias_conflict_counted` 不受影响），仅剧情注册表启用 `merge`。实测：`Noir`→菲林士多、`Amalfitano`/`阿马尔菲塔诺`→阿马尔菲塔诺村 |
| `by_hash(h, doc_id=...)` | 证据块按 `doc_id` 归位（重复 hash 不再错指视频） |
| `tokenize` CJK 相邻性 | 只对相邻 CJK 串拼二元组，消除 `暴。雨→暴雨` 假词元 |
| `stats()` 只读观测 | 新增 `zero_degree_entities`、`alias_reassigned`；`type` 含 `\|` 的脏值在**统计视图**归一到首类型（不写回文件） |

### P5 评测基建（本轮最关键的"能测"能力）
- 新增 `scripts/eval_plot_rag.py`：300 题全量/分层抽样、**oracle 天花板**、严格通过率 / 块精度 / 答案块率 / oracle recall / MRR、延迟分位、**路径归因**、**10 条离题负样本**、按 6 个维度分层、`--baseline` 回退判定、`--check-targets` 验收线自检；报告记录 `argv` + 配置快照 + 数据文件指纹，**同参数复跑逐位可比**。
- 三个脚本统一改走 `build_plot_registry`（评测 = 生产装配路径）。

## 4. 消融实验（为什么最终默认值长这样）

全部为 300 题全量、生产配置、同 seed：

| 配置 | 严格% | 块精度 | 答案率 | MRR | 离题注入 |
|---|---|---|---|---|---|
| 旧实现（基线） | 46.0 | **0.356** | **0.239** | **0.328** | 36 |
| k=60 + 权重 edge1.0/mention0.7（初版默认） | 42.0 | 0.300 | 0.215 | 0.309 | 0 |
| k=60 + mention0.8 | 44.0 | 0.313 | 0.222 | 0.312 | 0 |
| k=3 + mention0.8 | 44.7 | 0.298 | 0.204 | 0.311 | 0 |
| k=3 + mention1.5 | 45.0 | 0.327 | 0.217 | 0.311 | 0 |
| k=3 + mention2.0 | 46.3 | 0.326 | 0.216 | 0.306 | 0 |
| **k=3 + 等权（最终默认）** | **46.0** | **0.338** | 0.226 | **0.326** | **0** |
| k=3 + 等权 + **不分组**（交错） | 46.0 | 0.281 | 0.188 | 0.251 | 0 |
| **关掉两个种子门控** | 46.0 | 0.286 | 0.205 | 0.307 | **26** |
| 纯提及序（edge=0） | 39.3 | 0.249 | 0.161 | 0.227 | 0 |
| idf 稀有名字加权（替代旧口径） | 42.0 | 0.300 | 0.215 | 0.309 | 0 |

**三条被数据推翻的假设（如实记录）**：
1. **"稀有名字加权（idf）更好"** —— 不成立（42.0 vs 46.0）。ASR 语料里"反复提到某角色"的块往往正是该角色的主场戏（答案块），稀有别名命中多为顺带一提。→ 默认回到旧口径 `count`，`idf` 保留为可选模式。
2. **"RRF 默认 k=60"** —— 有害（−4pt）。k 大时名次几乎不影响融合分，融合退化成"通道优先序"。→ `k=3`。
3. **"图路应独占 top_chunks 名额"** —— 有害（−9pt）。并集口径下块数就是覆盖度。→ 恢复旧预算语义。

**门控的成本 = 0**：关掉门控严格通过率**完全不变**（46.0 vs 46.0），却换来 26 块离题注入；那 12 道被门控清空的题（4%）在基线上**全部也是错的**（0/12 通过）——它们本就是语料缺口（复乐园篇/迁流的盛宴篇/芝诺的英文等）。

| 指标 | 优化前 | 优化后 | 变化 |

| 答案块率 | 0.239 | 0.226 | −0.013 |
| MRR | 0.328 | 0.326 | 持平 |
| oracle recall | 0.327 | 0.303 | −0.024 |
| 平均返回块数 | 4.83 | 4.59 | −0.24 |

| 300 题检索总耗时 | 1774s | **67s** | 26× |
| 路径归因 | 不可测 | edge 787 / mention 581 / lexical 10 | 新增能力 |

**逐题翻转**：新增通过 11 题｜转为失败 11 题 —— 两个排序在总量上等价，但**答对的是不同的题**：
- 分层看：**multi-hop 15/60 → 19/60**（+4）、reasoning 10/30 → 7/30（−3）、factoid 109/200 → 108/200、temporal 持平。
- 灰机 14 题（生产配置）：**10/14 → 11/14**；独立跑 `--top 10`=12/14、`--top 5`=11/14（历史 13/14 是非生产配置下的旧记录，且其 `argv` 未落盘）。
- 块精度微降的直接原因：结果集里边证据占比 27% → 58%（这是"让图结构真正参与"的代价），而本指标是"块含证据词的占比"，边证据块天然比"点名块"命中率低。
