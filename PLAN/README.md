## 二、诊断修正（2026-09-16 勘查后）

初版诊断认为「语义索引未启用」是病根。**实测后修正：语义层其实在工作。**

### 已排除的误判

| 说法 | 实测结论 |
|---|---|
| 「语义索引不存在」 | ❌ 索引**已建好**：9021 块全填充，bge-m3 / 1024 维，建于 2026-09-13 16:57 |
| 「`plot_embed_model` 是死配置」 | ❌ 接线正确：`factory._build_plot_embedder()` 会读它，`.env` 里也已配 `bge-m3` |
| 「语义层被静默停用」 | ❌ 实测查询 R003 返回了 `path=semantic` 的块；评测 trace 显示语义通道命中率 98%、贡献 640 次 |
| `build_plot_index.py --status` 报 nomic | ⚠️ 该脚本用**全局** `embed_model` 比对，属**脚本自身口径问题**，不代表剧情层状态 |

### 修正后的真实病根

**病根 A：多跳题的证据组覆盖不全（主因）**

题集的 `evidence` 是**多组**，严格口径要求**每一组都被覆盖**才算 PASS。以 R003 为例：

```
题面：洞穴的囚徒篇里海盗船上的歌手是谁？
ref ：星锑（Regulus）
evidence：[["Regulus","星锑"], ["Sotheby","苏芙比"]]
```

检索召回了含「星锑」的块（第 0 组 ✅），但 top-k 里没有含「苏芙比」的块（第 1 组 ❌）→ 整题 FAIL。
**这不是标注错误**，而是这道 multi-hop 题要求同时凑齐两个角色的证据。

**病根 B：描述性查询定位首跳困难**

96 个缺口组里 **95 个的题面不含该组实体的任何名字**：

| 题面 | 参考答案 |
|---|---|
| 洞穴的囚徒篇里**海盗船上的歌手**是谁？ | 星锑（Regulus） |
| **负责照看乘客健康的牙医**英文名叫什么？ | Tooth Fairy（牙仙） |
| 被称作 **standkeeper** 的女性是谁？ | Zanetta（扎内塔） |

查询靠描述而非名字 → 需要语义匹配来定位首跳。语义通道已在工作，但召回结果**未必排进最终 top-k**。

**病根 C：索引里的实体向量已过期**

索引 `entity_count = 6784`，而当前图谱实体 **10406**（补抽后新增 3622）。实体向量用于「查询 → 实体」的语义链接（`semantic_link`），过期部分的新实体无法被语义链接命中。

### 由此得出的方向调整

| 原方向 | 调整后 |
|---|---|
| 启用语义索引 | → 索引已可用；改为**重建以刷新实体向量** + **参数调优** |
| 别名桥 | → 已验证无效（39 条入库后指标持平），**降级为维护项** |
| — | → 新增：**多跳覆盖策略**（本轮最高优先级） |

## 五、变更纪律

1. **先备份、后修改**（惯例：`data/knowledge/_archive/`）
2. 每次改动后必跑：`acceptance_plot_graph.py`（14 项不回归）+ `eval_plot_rag.py --baseline`（300 题 diff）
3. **禁止只看绝对值**——必须对基线做 diff
4. **指标异常先查口径**：曾发生「负样本题量 10 → 53 导致 0 → 54 被误判为回退」
5. 改动可回滚（索引与语料分离，删索引即回退纯词法）
6. **参数调优必须成对报告**（改了哪个参数、对哪个子集生效、整体是否劣化）
