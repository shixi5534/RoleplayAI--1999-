## F1 · 检索调试面板（六通道瀑布）★最高优先

**目的**：把 `retrieval_trace` 的六通道归因可视化了，直接支撑 B3 / B4 的调优决策。

**现状**：trace 数据只在评测脚本内部聚合（`trace_agg`），前端拿不到。

**需要后端配合（新增只读接口）**
```
GET /plot-graph/trace?q=<查询>&top=6
→ { query, channels:[{name, enabled, executed, hit_count, kept, skip_reason, weight}],
    final:[{text, via, path, edge, score}], latency_ms }
```

**前端内容**
- 输入框：输入查询 → 实时返回
- **通道瀑布图**：六个通道各显示「执行 / 命中 / 保留 / skip 原因」（横向条形 + 标签）
- **最终块列表**：每条显示 `via` / `path` / `edge` / 文本片段
- **对比模式**：同一查询显示「改动前后」两次结果（左旧右新）

**验收**：输入「洞穴的囚徒篇里海盗船上的歌手是谁？」能看清哪条通道贡献了哪些块、哪个通道被 skip。

## F2 · 实体 / 别名浏览器

**目的**：核查别名桥效果、排查噪声实体。本轮已验证 39 条灰机别名入库，需要可视化复核。

**后端**：已有 `GET /graph/entity`

**前端内容**
- 搜索框：按名字 / 别名模糊搜索
- 实体卡片：正名、类型、mentions、**全部别名列表**（标注来源：抽取 / 人工别名表 / 灰机桥）
- 关联展示：该实体参与的边（`src —relation→ dst`）、证据块 hash
- 噪声标记：`is_noise_entity` 命中的实体单独着色（当前 807 个）

**验收**：能查到「狼群」实体并看到 `Pavia` 别名来自灰机桥。

## F3 · 评测结果看板

**目的**：把 300 题 / 100 题的评测结果可视化，替代读 JSON。

**数据源（静态文件，无需后端）**
- `data/knowledge/_audit/eval_result_top{5,10,20}.json`（100 题）
- `data/knowledge/_audit/plot_rag_eval_report_*.json`（300 题）
- `data/knowledge/_audit/plot_rag_triage_r0.json`（失分归因）

**前端内容**
- 顶部指标卡：strict_pass / recall / MRR / 延迟
- **失分桶饼图**：别名桥缺失 79 / retrieval_gap 12 / …
- **分维度柱图**：type、difficulty、hop 三组的 strict_pass
- **逐题 diff 表**：新通过 / 新失败题号 + 题面
- 多报告切换：补抽前后 / 补桥前后对比

**验收**：打开即可看到「79 题别名桥缺失」的构成，并能下钻到具体题面。

## F4 · 图谱关系可视化

**目的**：直观检查图谱结构（10406 实体 / 7582 边），排查"抽到一半"的实体。

**前端内容**
- 以某实体为中心的 N 跳子图（默认 2 跳）
- 节点按 type 着色（角色 3541 / 物品 2114 / 概念 1725 / 地点 1369 / 组织 885 / 事件 580）
- 边显示 relation 谓语与 confidence
- 孤岛实体标记（度 = 0）

**注意**：10406 节点必须做**渐进加载**，不能一次性渲染。

## 实施纪律

1. 每个面板独立文件（`frontend/js/debug-*.js` + 对应 css），不改现有模块
2. 新增接口一律**只读**（GET），写操作（如重建索引）必须二次确认
3. 面板默认隐藏，通过调试开关进入
4. 每次前端改动后跑一次 `agent-browser` 端到端验证（项目既有惯例）
