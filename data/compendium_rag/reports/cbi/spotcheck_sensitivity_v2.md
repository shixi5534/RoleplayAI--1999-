# κ 的结论函数（在你标注之前算好）

- 仪器 **v2** · 随机行 **50** 条，机判在其中报非 clean **0** 条（全量 500 条里机判报 0 条）
- 闸门判据（与 `compute_kappa` 同一个 `gate()`）：`n>=30; degenerate => observed_agreement>=0.9(自选线); else kappa>=0.8(规格线)`
- 读法：**k = 人工在这 50 条里标出几条 soft**（人工臂从零开始标，不是「在机判上加几条」）；ov = 其中几条与机判重合。

## 这张表能定什么、不能定什么

- **这一臂走的是「观测一致率」那条线**（表里打 †）：机判在 50 条随机行里一个非 clean 都没报 ⇒ 单一类别 ⇒ κ 无定义。判据是 `一致率 ≥ 0.9`，**0.9 是我自选的阈值、规格里没有，你随时可以否决**。
  人工比机判多抓 **≤5 条**仍然 ✅；多抓 **6 条**就 ❌。
- **κ 那一列在这台仪器上不能读**：`k=0` 那行的 1.0 不是测出来的一致，是 `pe==1` 那支的约定（两边全同一类）；`k≥1` 全是 0.0 —— 这也是**退化**，不是一致性差。**别把这里的 κ=0 读成『判分器坏』**，它只说明 κ 这个指标在零正例率下失灵。
- **不能定 `soft ≤ 5`**：全量 N_soft 以 500 条机判实测（**0 条**）为准。抽样里机判报 0 条，×10 外推是 0 条 —— 拿它去覆盖总体计数纯属抽样噪声。抽检的用途是**一致性**，不是**流行率**。
- **若人工在抽检里抓到机判漏报**（多标的 soft 与机判不重合），正确动作不是外推数字，而是：把该情形写成 rubric 的一条判例 ⇒ 用统一尺子**重判全量 500 条**（25 批），两版读数一起报。这与 pass 1/pass 2 那次同源。

> 附：**v1 集**实测的机-机噪声底（`cbi_spotcheck_machine.json`，同一把尺、独立盲代理重判同样 52 条，一致率 94.2%，3 条分歧恰好就是机判报 soft 的那三条）—— 它是噪声底的**出处**，不是本机仪器的复测。v1 集发布读数因此按区间 **CBI ∈ [0.9844, 0.9874]** 报而不是单点；v2 集判分臂全 clean，同一逻辑下其区间上界同样是「上限（生成层完美）」那一档。
