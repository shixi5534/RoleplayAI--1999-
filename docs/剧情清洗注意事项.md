# 剧情清洗注意事项表

> **配套**：`剧情术语对照词表.md`（术语基准）、`剧情文件清洗清单.md`（执行清单）
> **适用**：所有对 `plot_cache/`、`plot_graph_*.json`、`plot_aliases.json`、`plot_corpus_*.json` 的改动
> **原则**：**先备份、再改数据、最后改代码；每步跑验收。**

---

## 一、格式约束（F）

| # | 约束项 | 具体规则 | 违反后果 | 校验方式 |
|---|---|---|---|---|
| F1 | 文件编码 | 全部 JSON/MD 必须 UTF-8（无 BOM）；Python 脚本调用统一加 `-X utf8` | 中文乱码、`锟斤拷`、别名混入天城文等异体字符（历史 P4 问题） | `file` 检查；审计脚本读不到预期 key 即报错 |
| F2 | JSON 结构 | `plot_cache/*.json` 必须保持 `{"entities":[{"name","type","aliases"}],"relations":[{"src","dst","relation","confidence"}]}`；不得增删顶层 key | `GraphCache` 反序列化失败，2477 块全部重抽 | `pytest -k plot` |
| F3 | 缓存文件名 | 必须为 `<chunk_sha1_16>.json`，小写十六进制，不得更名 | 缓存失效 → 触发全量 LLM 重抽（成本与耗时剧增） | `ls` 与 `PlotCorpus` hash 比对 |
| F4 | 文本归一 | 比较实体名统一走 `norm_name`＝NFKC + 小写 + 去首尾空格；**但** `Dr. S` / `mainstairwell` 一类空格变体对 ASR 有用，保留原样不强行归一 | 归并键不一致 → 同一实体分裂 | `graph_store.norm_name` (L32) |
| F5 | 缩进与换行 | JSON 落盘用 `ensure_ascii=False, indent=2`；MD 表格用标准管道表格 | 人工 diff 失效、无法 code review | 目视 + `git diff` |
| F6 | 空值处理 | `aliases` 允许空数组，不允许 `null`；`confidence` 必须 0–1 浮点 | 建图时 `NoneType` 异常 | 审计脚本 |

## 二、命名约束（N）

| # | 约束项 | 具体规则 | 违反后果 | 校验方式 |
|---|---|---|---|---|
| N1 | 以灰机 wiki 为准 | 规范译名一律以 https://res1999.huijiwiki.com/ 为准；wiki 无据的一律标 `status: pending`，**不得**凭印象或考据视频定名 | 事实错误进入角色人设，直接影响角色扮演回答可信度 | `verify_against_huiji.py` |
| N2 | 一人一名 | 同一实体在 `terms` 中只能有一个规范译名；化名（如淑女格蕾丝）作独立节点并用「化名」关系指向本体，不得互相挂 alias | 检索串味（历史 P3：`Lucy (Miss Stranger)` 让露西查询命中无名者） | 别名表交叉检查 |
| N3 | 禁止中英混写实体名 | `name` 字段要么全中文规范名，要么全英文官方名；禁止 `露西 (Lucy)` 这类混写 | 归并键失效、显示时中英夹杂 | 正则 `[\u4e00-\u9fff]` 与 `[A-Za-z]` 同时命中即报警 |
| N4 | 大小写 | 英文官方名保留原始大小写（`APPLe`、`Ms. Stranger`）；归并时走小写，展示时用原名 | 显示错乱、`APPLe` 被写成 `Apple` 与真名混淆 | `terms.en` 字段校验 |
| N5 | 头衔与人名分离 | 「司辰」「Ⅻ小队队长」等头衔不作为人物别名并入人名；用 `担任` 关系连接 | 头衔换人时图谱事实错误（司辰曾非维尔汀） | 人工复核 |
| N6 | 禁止代词与泛指 | 实体名不得为 `my father`、`her team`、`人类`、`城市`、`士兵` 一类 | 无法归并、无检索价值，且易被检索命中造成答非所问 | `is_noise_entity` + `noise` 清单 |
| N7 | 简称处理 | 组织简称（如 `Manus`、`Foundation`）可作为 alias 归并，但**不得**作为 `name` | 显示时丢失正式名称 | 建图时 `name` 取 `terms` 的 key |

## 三、一致性约束（C）

| # | 约束项 | 具体规则 | 违反后果 | 校验方式 |
|---|---|---|---|---|
| C1 | 端点接地 | 关系的 `src`/`dst` 必须能解析到**本块**某个实体的 `name` 或 `aliases` | `dangling_relation`，建图时整条边被丢弃 | `audit_full_corpus.py` |
| C2 | 有据可依 | 实体名或其某个别名必须出现在该 chunk 正文中 | `hallucinated_entity`（历史 364 块） | 同上 |
| C3 | 禁止自环 | `src != dst` | `self_loop`（历史 54 处） | 同上 |
| C4 | 置信度不得全平 | 同一块内所有关系 `confidence` 完全相同视为敷衍信号，仅记录不拦 | 质量信号丢失 | `flat_confidence` 标记 |
| C5 | 关系数 ≤ 实体数 | 超出视为臆造倾向 | `relation_heavy`（历史 94 块） | 同上 |
| C6 | 跨文档一致 | 同一实体在不同 chunk 的 `type` 必须一致；冲突时以 `plot_glossary.json` 为准 | 类型分裂，PPR 传播异常 | 建图后类型分布检查 |
| C7 | 译名用字统一 | 「兀尔德/乌尔德」一类异写必须全局统一（当前未定，见 S5） | 同一角色两个节点 | 全文 grep |
| C8 | 否定关系 | 禁止抽取否定谓语（`不是`、`未`）作为关系；应删除或改写为正向断言 | 历史 `阿尔卡纳—不是→Verta` | 审计规则待补（清单 C12） |
| C9 | 关系方向 | 抽取后必须核对主宾方向；介词短语（`on behalf of`）极易误抽为「持有」 | 历史 P2：`Miss Stranger—持有→Foundation` | `verify_against_huiji.py` 重点边复查 |

## 四、类型与关系约束（T / R）

| # | 约束项 | 具体规则 | 违反后果 | 校验方式 |
|---|---|---|---|---|
| T1 | 类型白名单 | 只允许 `角色 / 组织 / 地点 / 概念 / 物品 / 事件 / 时间` 七类 | 当前 42 种，含 `角色\|物品\|地点\|组织\|概念\|事件` 脏值 | `_JSON_SPEC` 改硬校验 |
| T2 | 越界回落 | 无法判定的类型回落 `概念`，**不得**丢弃实体 | 信息丢失 | 建图日志 |
| T3 | 类型不可臆造 | `技能/颜色/系列/歌曲/课程` 等一次性类型不得新增 | 类型爆炸 | 白名单校验 |
| R1 | 谓语必须中文 | 关系 `relation` 字段不得含拉丁字母 | `non_cn_predicate`（历史 2 处：escort / Bounty） | 审计脚本 |
| R2 | 谓语归一 | 必须命中 `CANONICAL_RELATIONS`（77 个）；未映射的直接丢弃 | 关系碎片化 | `canonicalize_relation` |
| R3 | 近义合并 | 「隶属／隶属于／属于」→ `隶属于`；「是／为」改为类型断言而非边 | 同一语义多条边，PPR 权重失真 | 人工 + 关系频次表 |
| R4 | 关系不承载属性 | 属性信息（时间、地点）写入边属性 `evidence/ts/story_time`，不得编造成新谓语 | 谓语爆炸 | 代码评审 |

## 五、别名约束（A）

| # | 约束项 | 具体规则 | 违反后果 | 校验方式 |
|---|---|---|---|---|
| A1 | 禁止自指 | 别名不得与正名相同（含 `norm_name` 相同） | `alias_self_ref`（历史 322 处） | `fix_backfill_alias_hygiene.py` |
| A2 | 禁止重复 | 同一实体内别名不得重复（`norm_name` 维度） | `alias_dup`（历史 24 处） | 同上 |
| A3 | 禁止整句 | 别名必须是名词性短语，不得是完整句子 | 历史 P6：维尔汀别名是一整句台词 | 长度 + 标点检查 |
| A4 | 禁止模板泄漏 | 别名不得包含 `曾用名/代称/昵称` 一类提示词占位说明 | 历史 P5：`伊万 (Madam Lucy的曾用名/代称/昵称)` | 关键词黑名单 |
| A5 | 禁止异体字符 | 别名不得含天城文、 emoji、控制字符 | 历史 P4：`斯特्र昂德` | Unicode 类别检查 |
| A6 | 空格变体例外 | `Dr. S`/`Dr.S`、`mainstairwell`/`main stairwell` 对 ASR 有用，**故意保留**不归一 | 强行归一反而丢召回 | 人工白名单 |
| A7 | 合并语义 | 合并进 `plot_aliases.json` 时按 key **取并集**，禁止覆盖已有条目 | 丢失人工校对成果 | 合并前 `cp` 备份 + diff |

## 六、时间与来源约束（TS / S）

| # | 约束项 | 具体规则 | 违反后果 | 校验方式 |
|---|---|---|---|---|
| TS1 | 区分两种时间 | `pubdate`＝视频发布日期（现实时间）；`story_time`＝剧情内发生时间。**不得混用** | 时间轴排序错误 | 字段命名强制区分 |
| TS2 | 未知即标空 | 剧情内时间未确认时写 `null`，**禁止猜填** | 错误事实污染时间轴 | 时间轴文档 `status` 字段 |
| TS3 | 时间粒度 | `story_time` 用 `{ "era": "1999-12-31", "precision": "day" }`；精度不足时 `precision` 取 `year`/`decade`/`unknown` | 精度丢失或被误当作精确值 | schema 校验 |
| TS4 | 非线性叙事 | 回溯/闪回内容按**剧情内发生时间**归档，不按出现顺序 | 时间轴错乱 | 人工标注 |
| S1 | 来源分级 | `source_kind` 取值仅 `canon`（主线 ASR / 官方 PV）或 `analysis`（考据解读） | UP 主主观推断被当作剧情事实（见清单 C6） | 语料层字段校验 |
| S2 | 检索默认 | 检索默认只取 `canon`；`analysis` 仅作补充证据并降权 | 核心问答被污染 | 检索层过滤 |
| S3 | 考据可作译名依据 | `analysis` 文稿可用于**反查官方译名**，但不得作为事实入图 | 事实与推测不分 | 人工把关 |
| S4 | UP 主标注 | 每个 doc 必须保留 `uploader` 与 `bv`，便于溯源 | 无法回溯取证 | `plot_corpus` 字段检查 |

## 七、流程与工程约束（P）

| # | 约束项 | 具体规则 | 违反后果 | 校验方式 |
|---|---|---|---|---|
| P1 | 先备份 | 改 `plot_aliases.json` / `plot_cache/` / `plot_graph_*.json` 前必须 `cp` 备份并带日期后缀 | 不可逆丢失（历史已靠 `bak_prehalluc` / `bak_prehuiji` 救回两次） | 备份文件存在性 |
| P2 | 零 LLM 重放优先 | 仅改别名/元数据时，用 `--build-graph` 重放缓存重建，**不重新抽取** | 无谓的 LLM 开销与结果抖动 | `extracted: 0 / cached: 2477` 日志 |
| P3 | 每步必验收 | 每步后跑 `audit_full_corpus.py` + `acceptance_plot_graph.py` + `pytest -k "plot or graph"` | 缺陷累积 | 三项全绿 |
| P4 | 不破坏现有挂接 | 新增能力以**新增文件**方式提供（如 `plot_glossary.json`），不改现有文件结构 | 回归风险 | `pytest` 529 项基线 |
| P5 | 改代码先加测试 | 修改 `is_noise_entity` / `canonicalize_relation` / `load_alias_table` 前先补单测 | 无回归约束失效 | 测试覆盖率 |
| P6 | 幂等 | 所有清洗脚本必须可重复执行且结果一致 | 二次执行产生新缺陷 | 连跑两次 diff 为空 |
| P7 | 不改 `.env` / 不启服务 | 清洗为离线数据操作，不启动 uvicorn / 不改动运行时配置 | 影响线上服务 | — |
| P8 | 大文件谨慎 | `lore_wu_ming_zhe.json` 58 MB、`graph_wu_ming_zhe.json` 41 MB，读写前确认内存与磁盘 | 卡死 / OOM | 分块读写 |

## 八、扩展性预留约束（E）

> 为「时间轴」「人物去向图」「知识图谱联动」预留，当前**不实现**，但命名与结构必须提前锁定。

| # | 约束项 | 具体规则 | 说明 |
|---|---|---|---|
| E1 | 新增字段不破坏旧读 | 新增 `story_time`、`narrative_order`、`source_kind`、`whereabouts` 一律**可选字段**，缺省时行为与现在一致 | 保证向后兼容 |
| E2 | 时间轴单一事实源 | 剧情时间轴统一维护在 `data/lore/<cid>/plot_timeline.json`，图谱只**引用** `event_id`，不复制数据 | 避免两处不一致 |
| E3 | 人物去向独立建模 | 去向 =（角色, 时间点, 地点, 阵营, 状态）元组，存 `data/lore/<cid>/plot_whereabouts.json`；与图谱用 `character_id` 关联 | 见时间轴文档 §四 |
| E4 | ID 稳定性 | `entity_id` 继续用 sha1 确定性生成；新增字段不得改变 ID 计算方式 | 否则全图 ID 失效 |
| E5 | 预留但不预建 | 未确认的时间点写 `null` 并标 `待补充`，**禁止**用版本号充当剧情时间 | 防止 S6/S8 污染 |
| E6 | 图谱只存事实 | 图谱存「谁在何时做了什么」；时间轴存「顺序与年代」；去向图存「位置与阵营」。三者通过 ID 关联，职责不交叉 | 见联动文档 |

## 九、禁止事项速查

| 🚫 禁止 | 原因 |
|---|---|
| 把考据/解读视频的说法当剧情事实入图 | UP 主主观推断，非官方 |
| 把版本号（3.7）当作剧情内时间 | 版本是现实更新序，非剧情时间 |
| 猜填未确认的译名或年代 | 事实错误进入人设，比缺失更危险 |
| 用 `rm` 删除备份或缓存目录 | 历史已两次靠备份救回 |
| 覆盖 `plot_aliases.json` 已有条目 | 丢失人工校对成果 |
| 给「露西」和「无名者」互相挂别名 | 官方明确是两个角色 |
| 让别名表依赖 `analysis` 类来源 | 只允许 wiki 与官方文本 |
