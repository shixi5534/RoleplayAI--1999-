## 1. 真正的瓶颈（已定位）

失败 105 题中约 **76–79 题**是「描述性、查询里不含任何实体名」的问法（例：「海盗船上的歌手」→ 星锑）。代码机制：

- `plot_graph.py::PlotGraphRetriever.retrieve()` 中 `seeds` 为空（约 L1499）→ 语义**块**通道被短路，拿不到任何实体相关的语义块。
- 语义**实体链接兜底**（`semantic_link_min`，约 L1452）生产环境 = `0.0` → 永不触发，等于没有这条补路。
- `margin_histogram` 显示 6 个无种子候选得分全部 `<0.35`，所以即使把开关打开，当前也链接不上（dead lever）。

> 注意：`bucket_attribution` 在多次跑次间数字不稳定（79→76→0），不可作指引；判断一律以 ground-truth `items` 为准。

## 3. 修复路径（两条，先做 A）

### 路径 A：描述性查询 → 实体解析（解决「seeds 为空」）

- **思路**：当 `seeds` 为空时，用 LLM 或 cross-encoder 把描述性 query 解析成候选 canonical 实体（top-K），再回填 `seeds`，让后续 edge/mention/semantic 通道正常跑。
- **可复用资产**：
  - `docs/实体识别与查询扩展_20260917.md`（实体识别与查询扩展方案）
  - `docs/别名桥v2与失分归因复核.md`（注意：别名桥 v2 已上线但**零提升**——它依赖 query 里已有实体 token，对「无实体名」无效；本路径补的是 LLM/语义解析，不是关键词别名）
  - `data/knowledge/_audit/huiji_alias_bridge_v2.json`、`canon_names.json`（规范名表）
- **实施步骤**：
  1. 在 `retrieve()` 的 `seeds` 为空分支，新增「描述性解析」子流程：调 LLM/rerank 产出 top-K 候选 canonical entity（K=3~5）。
  2. 候选实体回填 `seeds`，后续通道正常跑。
  3. 置信度低于阈值时**不强行注入**（避免噪声实体污染），阈值初设需校准。
  4. 新增 eval 开关 `--descriptive-resolve on|off`，做子集 + 全量对照。

### 路径 B：校准 / 激活 `semantic_link_min`（解决「实体链接兜底永不动」）

- **前提**：当前 6 个无种子候选 margin 全 `<0.35`。`semantic_link_min` 从 `0.0` 调到能接住真阳的阈值，但必须基于**真实 margin 分布**标定（避免拉入大量无关实体）。
- **步骤**：
  1. 跑一次「无种子查询 × 候选实体」的 margin 全量采样（`_audit/diag_recall_cause.json` 已有部分数据可参考）。
  2. 画 margin 分布，选阈值：在真阳召回与误注入之间取平衡（接住真阳且不新增负样本）。
  3. 若真实数据里候选得分普遍 `<0.35`，说明 embedding/链接打分本身需增强——可结合路径 A 的解析结果作为种子。

> 路径 A 与 B 互补：A 解决「完全没有种子」，B 解决「有弱信号但不敢用」。**优先做 A**。
