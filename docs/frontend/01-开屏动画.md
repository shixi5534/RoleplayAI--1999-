# 01 · 开屏动画（需求 1）

> 对应 ADR：D06（每次播 / ≤1.2s 可跳）、D07（抄语法不抄素材）、D08（盖住多页重载）、**D22（JS 全挂接受黑屏，不写兜底）**、**D23（主体用纯 CSS 文字，不用 `logo.png`）**。
> 所属阶段：**P3**（依赖 P1b 的自动化网 + D17 的 B4 修复）。

---

## 1. 结论先说

**1999 官网的开屏不是"动画片段"，是一段"文字从模糊到清晰"的 CSS 式叙事。** 我们照抄它的**语法**，主体用**纯 CSS 文字「ROLEPLAY」**（D23），**零新增素材、零外部图片**。

四个动作，一条时间轴：

```
黑场 → ROLEPLAY 文字渐显（去模糊+轻微放大） → 金色横线从左画出 → 副标落位 → 定格等 Live2D
```

**唯一的关键设计判断**：开屏的**寿命不能是固定时长**。实测 Live2D 就绪时刻在 5460ms ~ 8629ms 之间浮（取决于视口和 GPU），固定 3s 会露秃，固定 10s 会让快机器白等。所以退场信号必须绑 **`live2d:init-done`** 事件。

## 2. 1999 官网实测（我们要抄的是什么）

测量对象：`roleplay-ai/.agent_tmp/v4/r1999site/`（官网静态镜像）里的 `img/loading/loading.webp`。

| 项 | 实测值 |
|---|---|
| 载体 | `img/loading/loading.webp`，**147 帧 / 1920×1080 / RGBA**，2,643,208 B |
| 帧时长 | **全部 0**（webp 无时基，**由 JS 逐帧驱动**） |
| 背景 | 纯黑（f0 平均亮度 0.00） |
| 元素 1 | 中央「REVERSE」字样，f1 起出现，bbox `(696,424,1216,520)` ≈ 520×96 @1920 |
| 元素 2 | 字下米金**点状装饰弧线**，f30 后加入，bbox 撑到 `(680,360,1216,600)` |
| 变化结束 | **f70 左右**（亮度 7.86 后恒定，f80~f146 完全静止） |
| 黑场 | **起手 1 次（f0）**；**无收尾黑场** |
| 副指示器 | 另有一个 `img/loading/load.gif`，116×116，**150 帧 × 30ms = 4500ms** |
| 容器 | `#loading { position:absolute; z-index:100; background:rgba(0,0,0,1); transition:all .3s }` |
| 文字色 | **`#BBA893`**（暖米金） |

### 2.1 三条可直接搬的结论

1. **纯 CSS 播不了那个 webp**——每帧 `duration=0`，1999 自己也是 JS 驱动的。所以**不要试图"抄那段动画文件"**，要抄它的**节拍**：黑场起手 → 单元素渐显 → 一条装饰线延迟画出 → 定格。
2. **品牌色同族**：官网 `#BBA893` vs 本站 `--accent: #c9a86a`，同一个米金色系，**不需要调色**。
3. **没有收尾黑场**，是直接过渡到内容。我们的做法也一样：`opacity 1 → 0` 淡出，不做二次黑场。

### 2.2 按"变化集中在 f70、30fps 推定 ≈2.3s"折算的时间轴（**推断，非官网原值**）

| 时段 | 动作 |
|---|---|
| 0–120ms | 全屏 `#000`（写在 HTML 里就有，不等 JS） |
| 120–620ms | `.splash-word`「ROLEPLAY」：`opacity 0→1` + `filter blur(8px)→blur(0)` + `scale .96→1.0` |
| 620–1000ms | 金线（`::after`）：`scaleX(0)→1`，`transform-origin: left`，`opacity 0→.65` |
| 1000–1400ms | 副标 `RoleplayAI · 无名者`：`opacity 0→1` + `letter-spacing .44em→.30em` |
| 1400ms–收尾 | 等待态：只留一条呼吸光 |

## 3. 首帧代价实测（为什么开屏必须是"静态 DOM + CSS"）

这一节决定技术选型，不是装饰。

| 测量项 | 1280×720 | 1920×1080 | 1440×900 | 390×844（移动） |
|---|---|---|---|---|
| responseEnd | 42.5ms | 245.5ms | — | — |
| DCL | 196.8ms | 247ms | 258ms | — |
| load | 263.8ms | 247ms | — | — |
| **首帧** | **224ms** | — | — | — |
| **init-done** | ~7.4s | **8629ms** | **7552ms** | **5460ms** |

三组对照实验（1280×720）：

| 组 | DCL |
|---|---|
| A 基线（全量 JS） | **418.7ms** |
| B 关掉所有 JS | **247.2ms** |
| C 极简 1KB 页 | **30.5ms** |

⇒ **JS 只值 ~170ms。瓶颈 100% 是那 7.5 MB 的模型，不是脚本。**

### 3.1 三种首帧方案的实测对比

| 方案 | 首帧 | 评价 |
|---|---|---|
| ① 纯 CSS + 静态 DOM | **≈224ms** | ✅ **采用** |
| ② JS 生成 DOM | ≈394ms | ❌ 且可能先闪一帧裸骨架 |
| ③ Canvas 绘制 | ≥300ms | ❌ swiftshader 下再 +1~2s，绝不可用于开屏 |

### 3.2 ⇒ 开屏窗口 = 224ms ~ 7357ms，约 **7.1 秒**

这就是为什么 §1 说"寿命不能固定"。更精确地说：

- **下界 224ms**：太早退场等于没播（用户看不到任何东西）。
- **上界 8.6s**：swiftshader 下实测 `init-done` 到 8629ms。
- **因此**：最小展示时长设 **1400ms**（跑完 §2.2 那条时间轴），最大等 **20000ms**（兜底），中间完全由事件驱动。

## 4. 与现有 `#live2d-loading` 的关系

**结论：开屏「包住」loading，不是替换它。**

现有 loading 链路有四条：

| 链路 | 位置 | 行为 |
|---|---|---|
| 面板本体 | `frontend/index.html:72-75` + `frontend/css/index.css:564-586` | spinner + 「正在唤醒数字人…」，`z-index: 4` |
| 成功 | `frontend/js/live2d-bootstrap.js:35-40` | 收到 `live2d:init-done` → 加 `.hidden` |
| 失败 | `frontend/js/live2d-bootstrap.js:18-33`（`showStaticError` / `showErrorText`）+ `:42-51` | 显示错误提示 |
| 兜底 | `frontend/js/live2d-bootstrap.js:7-14` | `setTimeout(..., 8000)` 强加 `.hidden` |
| **第二条隐藏路径** | `frontend/js/chat.js:533-535` | `finally { if (loadingEl) loadingEl.classList.add("hidden") }` |

**`frontend/js/live2d-bootstrap.js` 全文只有 53 行**，改动面很小。

### 4.1 必须一起改的两处

| # | 问题 | 改法 |
|---|---|---|
| B4 | `frontend/js/chat.js:533-535` 的 `finally` 与 `live2d:init-done` 路径**重复**，会让开屏还没结束时 loading 就消失 | 删掉那句，或加 `&& !splashPlaying` 守卫 |
| — | 现有兜底 `setTimeout(..., 8000)` **在 swiftshader 下已实测误触发**（8629ms > 8000ms） | 提到 **20000** |

### 4.2 层级

开屏层 `z-index` **≥ 80**。理由：现有层级令牌最高的是 `--z-toast: 60`（`frontend/css/index.css:51`），开屏必须盖住 toast 在内的所有东西。

现有 z 令牌完整表（`frontend/css/index.css:45-51`）：

```
--z-backdrop: -2;  --z-veil: -1;  --z-stage-line: 3;
--z-stage-panel: 4;  --z-stage-top: 5;
--z-modal: 50;  --z-toast: 60;
```

## 5. 实现规格

### 5.1 三个文件的接线

| 文件 | 改动 | 说明 |
|---|---|---|
| `frontend/index.html` | `<body>` **第一个子元素**加静态 `#splash[aria-hidden="true"]` | 静态 DOM ⇒ 首帧就有，不等 JS |
| `frontend/css/splash.css`（新增） | 全部 keyframes + 降级 | 独立文件，`<head>` 里紧跟 `index.css` |
| `frontend/js/splash.js`（新增，约 60 行） | 只做三件事：`live2d:init-done` → 加 `.is-out`；`transitionend` → `remove()`；`setTimeout(20000)` 兜底 | **不生成 DOM、不跑动画** |

**CSP 无需改动**（全在 `'self'` 内）。

### 5.2 DOM 骨架

```html
<!-- frontend/index.html，紧贴 <body> 之后，z-index 80 -->
<div id="splash" aria-hidden="true">
  <div class="splash-mark">
    <span class="splash-word">ROLEPLAY</span>
    <span class="splash-rule"></span>
    <p class="splash-sub">RoleplayAI · 无名者</p>
  </div>
  <button class="splash-skip" type="button" aria-label="跳过开场">跳过</button>
</div>
```

**为什么是文字不是图（D23）**：

| 项 | 纯 CSS 文字（采用） | `logo.png`（否决） |
|---|---|---|
| 外部图片 | **0** | 1 张（13,794 B） |
| 可改字 | ✅ 改 `<span>` 内容即可 | ❌ 要重做图 |
| 原作标题风险 | **无** | 图上印着「REVERSE 1999 / 重返未来：1999」，**与本项目"无名者"人设串戏** |
| `letter-spacing` 收放当动画 | ✅ 天然 | ❌ 不能 |

> `logo.png` 仍然留在顶栏（`frontend/index.html:21`，`height:26px`）——那里是小尺寸品牌标识，不构成串戏。**开屏才是不该放大它的位置。**

### 5.3 关键帧（与 `frontend/redesign.html` 的动效令牌保持一致）

`frontend/redesign.html:74-78` 已经有一套动效令牌，**直接复用，不要另发明**：

```css
--e-out:  cubic-bezier(.16, 1, .3, 1);   /* 出场 */
--e-in:   cubic-bezier(.4, 0, .2, 1);    /* 退场 */
--d-micro: 160ms;  --d-base: 340ms;  --d-scene: 720ms;
```

对应 `frontend/redesign.html:509-514` 已有两个可抄的 keyframes：

```css
@keyframes heroRise { from { opacity:0; transform: translateY(26px) } to { opacity:1; transform:none } }
.boot       { animation: heroRise .9s var(--e-out) both }
.b1 {animation-delay:.08s} .b2 {.18s} .b3 {.3s} .b4 {.42s} .b5 {.54s} .b6 {.66s}
@keyframes ruleDraw { from { transform: scaleX(0) } to { transform: scaleX(1) } }
.rule-line  { transform-origin:left center; animation: ruleDraw 1.05s var(--e-out) .5s both }
```

（`.boot` 的注释原文：「首屏入场：一次编排好的序列，间隔 60–120ms」）

开屏专用三帧 + 主体字排版（**主体是文字，不是图**，D23）：

```css
@keyframes splashMark  { from { opacity:0; filter:blur(8px); transform:scale(.96) }
                          to { opacity:1; filter:blur(0);    transform:scale(1) } }
@keyframes splashRule  { from { transform:scaleX(0); opacity:0 }
                          to { transform:scaleX(1); opacity:.65 } }
@keyframes splashSub   { from { opacity:0; letter-spacing:.44em }
                          to { opacity:.72; letter-spacing:.30em } }

/* 主体字：ROLEPLAY。字距收放本身就是动画的一部分 */
.splash-word {
  display: block;
  font-family: var(--font-serif, Georgia, "Times New Roman", serif);
  font-size: clamp(28px, 5.2vw, 64px);
  font-weight: 400;
  letter-spacing: .30em;              /* 终值；动画从 .44em 收到这里 */
  text-indent: .30em;                 /* 抵消末字后的字距，让视觉居中 */
  color: #c9a86a;                     /* = --accent，与 1999 的 #BBA893 同族 */
  text-transform: uppercase;
  white-space: nowrap;
}
```

### 5.4 完整时间轴（落地值）

| 时刻 | 层 | 动作 | 曲线/时长 |
|---|---|---|---|
| 0 | `#splash` | 全屏 `#000`，`opacity:1` | 静态，无动画 |
| 120ms | `.splash-word` | `splashMark` + 字距 `.44em→.30em` | 500ms `--e-out` |
| 620ms | `.splash-rule` | `splashRule` | 380ms `--e-out` |
| 1000ms | `.splash-sub` | `splashSub` | 400ms `--e-out` |
| 1400ms | — | **最小展示时长到点**，此后只等事件 | — |
| `init-done` | `#splash` | 加 `.is-out` → `opacity:1→0` | **700ms** `--e-in` |
| +700ms | `#splash` | `transitionend` → `remove()` | 同时给 `#live2d-loading` 加 `.hidden` |
| 20000ms | `#splash` | 强制 `.is-out`（超时兜底） | — |

**跳过**（D06）：0~1200ms 内任意 `click` / `keydown`（Esc/Space/Enter）⇒ 立刻加 `.is-out`。**≤1.2s 可点，之后不可跳**（再跳过就等于看黑屏）。

原本备了一版用 `frontend/assets/r1999/logo.png` 当主体。**用户选了纯 CSS 文字，此方案作废**，理由见 §5.2 的对比表（最关键：那张图上印着原作标题「REVERSE 1999」，在本项目里会串戏）。

**`logo.png` 仍不删**——顶栏 `frontend/index.html:21` 还在用它（`height:26px`），小尺寸品牌标识没问题。

## 6. 降级与无障碍

| 场景 | 行为 |
|---|---|
| `prefers-reduced-motion: reduce` | **不播动画**，黑场直接 `opacity 0`（100ms），保留最短 200ms 防闪 |
| Live2D 加载失败 | 错误提示**必须显示在开屏之上**（`.live2d-status` 的 z 要抬到 90，或开屏内部显示错误态）——**这是 P0.5-B3 的连带项** |
| 多页重载（D08） | `settings.html` / `knowledge.html` 返回 `index.html` ⇒ 模型重载 6.8~9.3s，**开屏自动撑住**（因为绑事件而不是固定时长，无需额外逻辑） |
| **JS 全挂** | **接受黑屏，不写任何兜底（D22 已拍板）** |

> **D22 已定：接受黑屏。**
> 理由：JS 全挂时 `#live2d-canvas` 本来也是空的、`chat.js` 也不会接管输入，整站本就不可用——黑屏是**诚实状态**。
> 为此在 `index.html` 里塞一句内联 `<script>` 会破坏「禁止内联 script」硬规则 5，**收益不值**。
> ⇒ **P3 不写 `<noscript>`、不写内联兜底脚本。**

## 7. 验收标准

| # | 验收项 | 判据 |
|---|---|---|
| 1 | 首帧 | 224ms ± 60ms 内已见开屏（CDP `Page.startScreencast` 取首帧） |
| 2 | 最小展示 | ≥1400ms（写死的 `setTimeout` 门闩） |
| 3 | 退场绑定 | 拔掉 `live2d:init-done` 派发 ⇒ 走 20000ms 兜底，不卡死 |
| 4 | 跳过 | 600ms 时点任意处 ⇒ 700ms 内开始淡出 |
| 5 | 与 loading 的关系 | 开屏可见期间 `#live2d-loading` **不得**提前 `.hidden`（B4 已修） |
| 6 | reduced-motion | 无动画、无闪烁 |
| 7 | 多页往返 | `settings.html` → `index.html` 全程有开屏覆盖，无裸骨架闪 |
| 8 | 零新增体积 | `git diff --stat frontend/assets/` 为空 |

**测量局限（写进文档以免误判）**：
- `performance.getEntriesByType('paint')` 在本环境**恒返回 None**，不能用。
- `page.screenshot()` 每张耗时 2~7s 且会堵主线程，**不能用来测首帧**。
- ⇒ 唯一可行手段：CDP `Page.startScreencast`。复现脚本见 `99-实测数据索引.md`。
