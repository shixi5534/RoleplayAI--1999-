## 5. 关键机制备忘

1. **RRF 是排名制**：`w × 1/(k+rank)`；深排名候选调参不可救，只能改**池构造**或换**打分制重排**。
2. **collect 文件的 `hit` 字段是 hit@top_k（=30）**，不是 hit@6；须用 `rank<=6` 重算。
3. **`_rank_rerank_lab.py` 会在传入的任何题集上重新拟合** → 其盲测数字是**样本内**；
   真实检验必须**冻结**他处选定的配置。
4. **PPR 是主要耗时**（1–3s/题）；批量实验务必**先缓存通道结果再扫参**。
5. **CE fp32 CPU ~110s/题**；ONNX int8 快 6 倍但**无增益**。

## 8. 工程坑（更新版）

- **⚠ PowerShell `Set-Content -Encoding UTF8` 会破坏 UTF-8 中文源码**：本会话它把
  `_p3_lexfirst_refit.py` 的中文串变成 mojibake（`鈥?`）并写 BOM，导致 SyntaxError。
  **对策**：改文件用 `write`/`edit` 工具或 Python，**不要**用 PowerShell 做文本替换。
- **长任务 stdout 缓冲**：`python s.py > log` 不刷缓冲、看不到进度；用 `python -u`。
- **`git rm -r --cached` 会误暂存大量删除**：本会话一次操作暂存了 **5087** 个删除；
  用 `git reset` 后改为**精确路径** `git add`。落盘后务必查 `--diff-filter=D` 计数。
- **子代理读大 JSON 易失败**：本会话 C 分片失败 2 次（~1MB JSON）。
  对策：先导出**纯文本分片** + 指示用 `read` 的 offset/limit 分批读；切成 ≤11 万字的小片。
- 继承：`data/` 在 gitignore 内需 `git add -f`；`core.autocrlf=true` 已由 `.gitattributes -text` 修正。

## 9. 纪律（继承 + 本会话追加）

**继承**：指纹=回滚锚点（以 SHA-16 为准，图内嵌 `fingerprint` 是常量不作判据）；
修复者永不复核自己；判据先于结果；涨跌同表+逐题题号；FAIL 即回滚并入库归因；
一切数字**冷测**作数、一切读数**双通道**作数；落盘后一律**冷启动**复评（禁暖进程自评）。

**本会话追加**：
1. **留出集优先**：任何"能力声明"必须报**未参与开发**的题集上的成绩；调参集数字标注样本内。
2. **权重必须冻结**：跨集合"再拟合一次"会摧毁泛化（实证 0.8724→0.7427 崩盘）。
3. **先做通道 oracle 再调参**：区分"候选缺失"与"名次太深"，避免调错方向。
4. **对"系统失败"先归因审计**：分清"检索不行"与"gold 本身有问题"（本会话 3/14 属后者）。
5. **盲测集须核验偏置**：比对题面↔gold 字面重叠分布，排除措辞泄漏。
6. **否决的干预不留代码**，只留证据（本会话 6 类否决 + RM3 均零改动）。
7. **交接文档必须自校验**：`_verify_handover_facts.py` 逐条比对文档数字与磁盘证据。
