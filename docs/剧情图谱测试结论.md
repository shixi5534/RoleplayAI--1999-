## 二、本轮发现并处理的缺陷

### D1 · `plot_include_weak` 默认关闭，图谱检索实质失效 🔴 严重（已修复）

- **现象**：16 条查询里 9 条退化成纯词法兜底；补抽的 395 块召回 0 个。
- **复现步骤**：
  ```bash
  .venv/Scripts/python.exe -X utf8 scripts/test_plot_graph_retrieval.py --selftest-backfill 60
  # 修复前：图谱路径 7/16，补抽块 0/395
  ```
- **根因**：`WEAK_EVIDENCE_MIN = 2`，而实测 4302 条边里 **4289 条只有 1 条证据（99.7%）**。
  因为每块独立抽取，同一条边在不同块里谓语措辞略有差异，无法自然累积到 2 条证据。
  默认 `include_weak=False` 直接把这 4289 条边全部过滤 → 图谱只剩 13 条边可用。
- **修复**：`src/roleplay/config.py` 的 `plot_include_weak` 默认改 `True`；
  `factory.py` 的 `getattr` fallback 同步改 `True`。
  **未改动** `PlotGraphRetriever/Registry` 类签名默认（测试 `test_retriever_weak_edge_gated` 依赖其为 False）。
  孤证边本就有 `score *= 0.5` 降权，且仍受 `plot_edge_min_confidence` 约束。
- **验证**：图谱路径 7/16 → **16/16**；补抽块召回 0 → 10（固定查询）、0% → 70%（反向验收）。
- **防回归**：新增 `test_plot_include_weak_defaults_to_true`。

### D2 · 审计规则 `hallucinated_relation` 不解析实体别名 🟡 中等（已修复）

- **现象**：回填块 383/395 被误判为「关系臆造」。
- **复现步骤**：`python scripts/audit_full_corpus.py`（修复前 `hallucinated_relation=383`）。
- **根因**：判定只看关系端点的**字面串**是否出现在正文，不解析实体的 `aliases`。
  「中文正名 + 英文别名」是本项目合法写法（GraphRAG 归并依赖别名表），整片被误判。
- **修复**：`scripts/audit_full_corpus.py` 增加端点接地表 `endpoint_grounded`
  （端点串按正名/别名解析回实体，再取该实体是否有据）；判定口径同时从
  「两端都缺失」收紧为「**任一端无据**」，更贴合臆造语义。
- **验证**：`hallucinated_relation` 383 → 0，且未放过任何真实臆造。

### D3 · 超长查询导致连接被重置 🟡 中等（已缓解，残留部署层建议）

- **现象**：`q` 为 10000 字符时，客户端收到 `ConnectionResetError [WinError 10054]`，
  服务端日志**没有该请求记录**——请求未进入应用层。
- **复现步骤**：
  ```bash
  # 真实起服务后
  curl "http://127.0.0.1:8123/api/knowledge/plot-graph/search?q=<10000字符>"
  ```
- **根因**：URL 请求行超过 HTTP 服务器限制，在解析请求行阶段即被拒绝，
  属于传输层限制，FastAPI 参数校验无法介入。
- **修复**：`src/roleplay/api/knowledge.py` 的 `plot-graph/search` 给 `q` 加
  `max_length=200`（应用层拦截，覆盖正常输入）；实测超长请求现在返回规范的 **431**
  而非连接重置，且服务保持存活（异常后存活检查 = 200）。
- **残留建议**：431 仍是传输层行为。**建议**生产部署显式配置
  `uvicorn --limit-request-line 65536`，并在前端对输入框限长（≤ 200 字），
  让超限请求在本地就被拦下，避免打到服务端。同类 `/api/knowledge/search`
  等 GET 端点建议一并排查是否需同样限长。

### D4 · 剧情层产物版本 `plot-v1` 未落盘 🟢 建议（未修）

- **现象**：`PLOT_GRAPH_SCHEMA = "plot-v1"` 仅用于构建日志；落盘的
  `fingerprint.schema` 记的是通用库的 `GRAPH_SCHEMA_VERSION = "v1"`。
- **影响**：剧情图谱产物格式升级时，无法在加载期校验兼容性（`check_fingerprint`
  只能发现嵌入器/维度失配，发现不了剧情层格式变更）。
- **建议**：把 `PLOT_GRAPH_SCHEMA` 一并写入 `fingerprint`（如 `plot_schema` 字段），
  并在 `PlotGraphRegistry.get()` 中校验，失配时静默降级并告警。

### D5 · 补抽块反向验收 70%，非 100% 🟢 观察项（非缺陷）

- **现象**：60 个抽样补抽块中 18 个用自身实体名查不回来。
- **分析**：未召回块的首个实体多为高度数枢纽（暴雨 91 度、圣洛夫基金会 200 度、
  项目、拉普拉斯），PPR 排序时被更强、更多证据的边挤掉，属正常排序竞争。
  补抽真正要救的**冷门专名**（金预言、潘家园、巴比伦骰子、皮罗斯、曼佩刺杀、
  Ms. Stranger）在正向查询里 **100% 命中**。
- **建议**：若需进一步提升，可做「同一实体证据去重 + 结果多样性重排」，
  避免 top-k 被同一枢纽的相似边占满。
