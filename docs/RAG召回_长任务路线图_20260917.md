## P0（立即，1–2 天）

### T1 启用并标定 bge-reranker 精排
- **动作**：项目已有 `src/roleplay/core/knowledge/plot_rerank.py`（bge-reranker，未启用）。
  按文献两阶段形态接入：候选池 top-30~50 → cross-encoder 精排 → 取 top-6 进预算。
  对 k∈{20,30,50} 消融（文献峰值区），沿用 `--check-targets` 护栏。
- **验收闸门**：300 题 strict ≥ +8（199→≥207）、inject 不降、负样本失守不增、
  p95 增量 ≤ 100ms（精排 30–50 条在本地 GPU/CPU 的延迟需实测）。
- **依据**：rerank 是文献口径 RAG 栈单步收益最大的一步（+5~7 NDCG）；候选池 30–50 达峰。
- **风险**：本地推理延迟超预算（降级：池缩到 20；或 TEI 服务化）。

### T2 inject 装配顺序重排（位置效应，零成本）
- **动作**：`persona_prompt.build_plot_context` 装配时，按"证据覆盖度"重排：
  覆盖最关键证据组的块放开头与结尾，中间放次要块（Attention Basin：LLM 首尾注意力高）。
- **验收闸门**：300 题 inject ≥ +3、strict 不变（检索结果逐位一致，只动装配顺序）、
  负样本不变。纯装配层改动，可单独回滚。
- **依据**：Lost in the Middle（Liu 2024）/ Attention Basin（ACL 2026）。

### T3 补位重排灰度开启
- **动作**：keep=5 已是默认值（开关仍关）。走灰度：先 10% 流量 → 观察 strict/inject/负样本
  三日 → 全量。回滚 = 置 `ROLEPLAY_PLOT_RERANK_TOPUP_ENABLED=false`（no-op 路径）。
- **验收闸门**：线上采样 strict/inject 不低于离线读数 −2pt；负样本零新增。

## P1（本周）

### T4 HippoRAG 式融合：PPR 分布引导 dense 排序
- **动作**：实验脚本先行（不动生产）。当前语义通道按"名次 RRF"扁平融合；
  HippoRAG 用 PPR 实体分布加权 dense 检索与排序。实现 PPR 分数 × chunk-实体关联
  → 语义通道内重排，跑 300 题 + 新 200 题对照。
- **验收闸门**：multi-hop 子集 strict ≥ +8（45%→≥53%）；全量不回退；负样本不变。
- **依据**：架构同构（PPR+KG+dense），HippoRAG recall@5 83–96% vs 我们 45–50%，
  差距方向最明确；GFM-RAG 对比表确认 graph 结构对 multi-hop 的增益。
- **风险**：chunk-实体关联稀疏（部分块无实体）→ 无关联块保持原序。

### T5 章节摘要节点（RAPTOR 式）
- **动作**：为每个篇章生成摘要块（LLM 离线，1.4/1.7/1.9/1971 + 其他大章），
  入语义索引并给独立融合权重（或作为 chapter 通道的补充候选）。
- **验收闸门**：multi-hop strict 提升；no_full_ceiling 的 18 题中 ≥3 题出现
  "摘要块提供关键覆盖"；负样本不增（摘要块必须过 `semantic_min_score` 与门控）。
- **依据**：RAPTOR 分析——复杂 QA 显著依赖高层（非叶）信息；统一对比框架确认其低成本高效。

### T6 实体表清洗：别名漂移过滤
- **动作**：对 10406 条实体名表跑 anchor-drift 过滤（Sci-ZSEL 公式）：
  别名与本体/图邻居实体的相似度 ≥ 与本实体相似度 → 丢弃。
  预期清掉 story/time/Hey/today's game 类脏别名。清洗后重建实体向量索引。
- **验收闸门**：负样本 `search_entities` top1 分数分布显著下移（p50 0.656 → <0.55）；
  300 题链接数不显著下降（保真阳）；strict 不回退。
- **依据**：Sci-ZSEL 的漂移过滤正是治"LLM 别名指向邻居实体"；我们实体表脏已实测
  （负样本 top1 0.63–0.78 全是泛词实体）。
- **联动**：清洗后重跑"阈值可行性"——若真阳/噪声可分了，`semantic_link_min` 才有重开机会。

## P2（前置条件：有效 LLM key）

### T7 实体侧离线补名管线（Sci-ZSEL 形态）
- **前置**：`ROLEPLAY_LLM_API_KEY` 填入真实 key（现为 `ollama` 占位，deepseek 401）。
- **动作**：强模型对**实体定义**批量生成候选别名（而非对查询）→ T6 的漂移过滤 →
  并入别名桥 + `StaticMapIdentifier` 静态映射。在线零延迟。
- **验收闸门**：以"补名上界 +28"为天花板，实际 strict ≥ +8（300 题）；负样本不增。
- **依据**：Sci-ZSEL（实体侧生成省一个量级成本、跨语料复用；与人工同义词合并最佳）。

### T8 multi-hop 分解路由（Adaptive-RAG 模式）
- **动作**：轻量分类器/规则识别 multi-hop 查询（dims 里 hop=multi 的历史分布 +
  题干特征）→ 仅对这类触发"分解为子问题 → 各自检索 → RRF 汇合"。
  max_steps=3、单题 LLM 预算上限、超时降级为原查询。
- **验收闸门**：multi-hop strict ≥ +6；非 multi-hop 逐位不变（路由不误触发）；
  p95 增量 ≤ 300ms（仅作用于 ~20% 查询）。
- **依据**：Query Optimization Survey（多跳隐式 → decomposition）；EMNLP 分解线；
  Adaptive-RAG 按复杂度路由的生产共识。

### T9 语料侧 document expansion 消融
- **动作**：对 ASR 语料块做 doc2query/伪反馈扩展（为每块生成 2–3 个假设查询并入块文本
  或独立向量行）→ 重建索引 → 全量对照。
- **验收闸门**：strict ≥ +5、inject 不降、负样本不增；不达标即弃（与查询侧扩展不同，
  这是 SDR 在 ASR 语料上验证过的方向，但 Weller 2024 的噪声警告同样适用，必须实测）。
- **依据**：Cambridge TREC-8 SDR：doc expansion 55.29 vs 41.47（ASR 语料大收益）。

## 全局回滚原则

- 所有开关默认关（`plot_rerank_topup_enabled`、救援兜底、将来的 PPR 融合/补名）；
- 每项改动在 300 题 + 新 200 题**双题集**验证，双集非负才可灰度；
- 负样本失守条数（7/53）与新增泄漏（2）是硬闸门，任何一档恶化即回滚。

## 验收规则修订（2026-09-17 晚，T11 完成后生效）

> 背景：T5 实验证明 `strict_pass`（并集证据词覆盖）可被"追加名词表合成块"灌水——
> 把与题无关的全局 top-40 名表追加进结果，strict 195→214（+19）而 inject 完全不动。

- **铁律一**：任何"strict 上涨"必须同时满足 `strict_pass_retrieved`（抗灌水口径，
  排除 `metadata.synthetic=True` 的注入块）不降；只涨 strict 不涨 retrieved = 灌水。
- **铁律二**：真改善必带动 `inject_pass`；inject 不动或下降的方案一律不落地。
  历史验证：补名上界 inject +36、补位重排 +1 = 真改善；T5、CE 精排 inject 不动/下降 = 假。
- **铁律三**：合成块（摘要/名表/扩展文本）必须打 `metadata["synthetic"] = True`，
  否则属评测作弊；新口径要靠这个标记识别。

**当前唯一通过双口径检验的产出**：补位重排 keep=5（300 题 199/199，+4；
新 200 题 +1；inject −1；负样本不变）→ 可按 T3 走灰度。
