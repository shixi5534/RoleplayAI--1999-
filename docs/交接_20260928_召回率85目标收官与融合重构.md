## 4. 本轮核心发现（按重要性排序）

### 4.1 ⭐ 融合在稀释词面通道（最重要的结构性发现）

**证据**（盲测 206，官方路径）：`lex-only = 192/206 = 0.9320` vs `fused = 172/206 = 0.8350`。

**机理**：RRF 是**排名制**融合，每通道第 1 名都得同样的 `1/(60+1)`。
当 graph/mention/vector 各自把大量候选推到前列时，融合后的 top-6 被"分票"，
把词面通道**真正命中**的块挤出前 6。**权重扫描（w_lex 1→16）无法修复**（各档 ≤ 现状）。

**已实现修复**：`lex_first`（词面前 N 名提到最前，其余按融合序补足）→ 盲测 **+8.7pt**。

### 4.2 ⭐ 在盲测上重新拟合重排器会严重过拟合

| 做法 | 300cn | 盲测206 |
|---|---|---|
| 冻结 v6 权重 + 新池 | 0.8418 | **0.9223** |
| **在 300cn 上重拟合**后冻结 | 0.8724 | **0.7427**（down=37） |

重拟合在调参集上更高（0.8724）却在留出集**崩到 0.7427**。
=> **重排器权重必须冻结**；跨集合"再调一次"会摧毁泛化。这是本轮最重要的方法论警示。

### 4.3 ⭐ 3 道 miss 是**测试集 gold 缺陷**，不是系统失败

## 5. 关键机制备忘

1. **RRF 是排名制**：`w × 1/(k+rank)`。某候选在每个通道都排 14 名开外时，
   **无论权重如何都进不了 top-6**。→ 调参救不了深排名候选，只能改**池构造**或换**打分制重排**。
2. **collect 文件的 `hit` 字段是 hit@top_k（=30）**，不是 hit@6；比较时须用 `rank<=6` 重算。
3. **`_rank_rerank_lab.py` 会在传入的任何题集上重新拟合** → 其"盲测集上 0.94"是**样本内**数字。
   真实检验必须**冻结**他处选定的配置。
4. **盲测偏置已核验**：盲测与 300cn 的「题面↔gold 块」bigram 重叠几乎相同
   （均值 0.384 vs 0.364；高重叠 23.8% vs 24.0%）→ 盲测**无异常字面泄漏**。

## 8. 工程坑（更新版）

- **⚠ PowerShell `Set-Content -Encoding UTF8` 会破坏 UTF-8 中文源码**：本轮它把
  `_p3_lexfirst_refit.py` 的中文串变成 mojibake（`鈥?`）并写 BOM，导致 SyntaxError。
  **对策**：改文件一律用 `write`/`edit` 工具或 Python 写，**不要**用 PowerShell 做文本替换。
- **长任务 stdout 缓冲**：`python script.py > log` 在重定向时不刷缓冲，看不到进度。
  用 `python -u`，或写进度到文件。
- **PPR 是主要耗时**（~1–3s/题）。批量实验务必**先缓存通道结果再扫参**
  （本轮 `_fusion_restructure.py` 初版按 config 重算通道，慢 13×，已修）。
- **CE fp32 CPU ~110s/题**（206×60 对 >1 小时）。ONNX int8 快 6 倍但**无增益**。
- 继承：`data/` 在 gitignore 内需 `git add -f`；`core.autocrlf=true` + `.gitattributes -text`
  已修（勿再用 PowerShell 重写文本文件）；子代理读大 JSON 易失败 →
  先导出**纯文本分片**并指示用 `read` 的 offset/limit 分批读（本轮 6 分片中 C 分片失败 2 次）。

## 9. 纪律（继承 + 本轮追加）

**继承**：指纹=回滚锚点（以 SHA-16 为准，图内嵌 fingerprint 是常量不作判据）；
修复者永不复核自己；判据先于结果；涨跌同表+逐题题号；FAIL 即回滚并入库归因；
一切数字**冷测**作数、一切读数**双通道**作数；落盘后一律**冷启动**复评。

**本轮追加**：
1. **留出集优先**：任何"能力声明"必须报**未参与开发**的题集上的成绩；
   在调参集上的数字一律标注样本内。
2. **权重必须冻结**：跨集合"再拟合一次"会摧毁泛化（§4.2 实证：0.8724→0.7427 崩盘）。
3. **先做通道 oracle 再调参**：区分"候选缺失"与"名次太深"，避免调错方向（§4.4）。
4. **对"系统失败"先归因审计**：分清"检索不行"与"gold 本身有问题"（§4.3 三例）。
5. **盲测集须核验偏置**：比对题面↔gold 的字面重叠分布，排除措辞泄漏（§5.4）。
6. **否决的干预不留代码**，只留证据（本轮 6 类否决 + RM3 均零改动）。
