## 裁决 1：凯拉 / 塞西莉 / 莉莉 —— **保留为「无名者」的直接别名**

**结论**：维持现状，不改挂「化名」关系，不从 `plot_aliases.json` 剔除。

**当前数据实况**（`data/lore/wu_ming_zhe/plot_aliases.json`）：

```json
"无名者": ["Ms. Stranger", "Miss Stranger", "Ms. Grace", "淑女格蕾丝",
           "陌生人小姐", "无名之人", "格蕾丝", "莉莉", "凯拉", "塞西莉"]
```

`plot_glossary.json` 的 `terms.无名者` 与之同步，`status: verified`，
来源 `https://res1999.huijiwiki.com/wiki/无名者`。

**为什么这个决定有争议**（记录理由，便于日后复核）：
N07 存在「遭遇真实的凯拉」这类语境，剧中存在**冒充叙事**——
「凯拉」「塞西莉」「莉莉」可能是无名者使用过的身份，也可能是独立人物。
直接并成别名有串味（把别人的事迹算到无名者头上）的风险。

**选择保留的判断依据**：别名归并只取并集、可回滚；而改挂「化名」关系需要
先确认叙事事实，属于 M1a 联网核查的范畴，不该在数据层先行决定。

**复核触发条件**（满足任一即重新审议）：
1. M1a 联网核查时，灰机 wiki 出现独立的「凯拉」「塞西莉」「莉莉」角色条目；
2. N1 云端抽取完成后，这三个名字在语料中出现了与无名者**矛盾的上下文**
   （如同时同地出现、被他人以第三人称分别指称）；
3. Golden Query 中出现「凯拉是谁」类查询且召回质量明显异常。

## ⚠️ 顺带发现：格蕾丝 的指向不一致（**未裁决，需你定**）

现有数据里存在一个自相矛盾的地方：

| 名称 | 当前指向 | 说明 |
|---|---|---|
| `格蕾丝` | **无名者** 的直接别名 | 在 `plot_aliases.json` 的「无名者」别名列表里 |
| `Ms. Grace` / `Madam Grace` / `Grace` | **淑女格蕾丝**（独立节点） | `plot_glossary.json` 有独立词条 |

而 `terms.淑女格蕾丝` 的 note 明确写着：

> ＝无名者的化名。ID 6249；2.0「飞驰！明日之城」登场；「复乐园」证实为
> 圣洛夫基金会安插的卧底。**作为独立节点保留并通过『化名』关系指向无名者，
> 便于检索命中。**

也就是说，**中文形式走别名并入无名者，英文形式走独立节点 + 化名关系**——
两条路径不一致。后果：文本里出现「格蕾丝」时直接链接到无名者，
那条精心设计的「化名」关系边被绕过，检索时拿不到「淑女格蕾丝 = 卧底」这层信息。

**两个可选处理**（我没擅自改）：
- **A. 对齐到独立节点**：把「格蕾丝」从无名者别名表移除，加入淑女格蕾丝的别名。
  检索更准，但「格蕾丝」的提及不再计入无名者。
- **B. 对齐到别名**：反之，把 Ms. Grace / Grace 并入无名者，淑女格蕾丝节点降级。
  更简单，但丢失「化名 = 卧底身份」的区分。

**倾向 A**——因为 note 里已经明确了「作为独立节点保留」的设计意图，
不一致的是中文别名那一侧。但这会改变检索行为，需要你确认。

## 裁决 2：云端抽取走「对话分批产出」，不改 `.env`

**结论**：`scripts/cloud_extract.py --dump` → 云端强模型（在对话中产出）→ `--apply`。
不接第三方 API，不修改 `.env`。

**背景**：`.env` 当前是本地 ollama `qwen2.5:7b`，实测
`entity_precision 0.675` / `relation_precision 0.111` / `recall 0.15`——
约 89% 的关系是错的。

**为什么这个方案可行且安全**：
- 抽取缓存的键是 **chunk 文本 sha1**，与模型、来源无关 → 任何来源的产出
  只要按格式写进 `plot_cache/<cid>/<hash>.json`，`--build-graph` 就能零 LLM 重放；
- 全程不启服务、不装依赖、不花钱、可随时暂停；
- 每批 `--dry-run` 先验，确认无误再落盘。

**流程**：

```bash
python -X utf8 scripts/cloud_extract.py --plan --size 40          # 看总量与批次数
python -X utf8 scripts/cloud_extract.py --dump --batch 0 --size 40 # 导出 md
#   → 由云端强模型产出 _cloud/<cid>/batch_000.jsonl
python -X utf8 scripts/cloud_extract.py --apply --batch 0 --dry-run # 先验
python -X utf8 scripts/cloud_extract.py --apply --batch 0           # 入库
python -X utf8 scripts/cloud_extract.py --status                    # 查进度
```

**硬约束已内置到 dump 的规范段**（违反即被 `--apply` 静默丢弃）：
7 类 `type` 白名单、77 条受控谓语、端点必须在本块实体内、禁自环
（**含正名与别名之间、别名与别名之间**）、禁代词泛指。
