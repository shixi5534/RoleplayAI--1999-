# RAG 召回 · 上界探测与计划修订（2026-09-17）

> 本文是对 `docs/RAG召回优化下一步计划_20260917.md` 的**实测复核**。
> 结论：原计划的两条修复路径，一条收益上限只有约 5 题，一条被负样本数据证伪；
> 主战场既不是「seeds 为空」，也不是「融合层挤出」，而是**召回面**——正解块压根没进入任何通道候选池。
>
> 本文所有数字均由只读诊断脚本产出，检索行为与生产配置**零改动**。

## 2. 对原计划两条路径的判定

### 路径 A（seeds 为空 → 描述性解析回填）：收益上限约 5 题，**不应作为主修复**

- 「查询里没有实体名」是**文本现象**，「`seeds` 为空」是**代码事实**，两者不是一回事。
  实测 297/300 题 `link_detailed` 能拿到 `path=exact` 的精确命中，只有 3–6 题真正无种子。
- 即使这 5 题全救回来，strict 最多 195 → 200，距目标 210 仍差 10 题。
- 注：`plot_graph.py` 里的种子门控注释自己就写着「失败题的种子几乎总是非空（只是选错了）」。

### 路径 B（校准 `semantic_link_min` 激活实体链接兜底）：**数据证伪，不要做**

- 真阳实体的余弦分数 **低于** 负样本：真阳 p50 = 0.512，负样本 top1 p50 = 0.656（p10 也有 0.554）。
- 任何能接住真阳的阈值（≤ 0.45）会让 **100% 的负样本**被链接上；阈值提到 0.60 能挡掉 25% 负样本，代价是真阳接住率归零。
- 根因：实体向量索引里混有 `story` / `time` / `Hey` / `today's game` 这类泛词实体（全表 10406 条），它们与任何查询的余弦都在 0.6+。**单阈值在原理上不可分**。

### 附带结论：救援兜底为什么「无害但无效」

- 旧归因「100/105 正解块被融合挤出」不成立：真正被挤出的只有 **27 题**。
- 救援兜底只能作用于这 27 题，且它保底的是「通道顶部块」而不是「正解块」→ 实测 195→197，与这个上限自洽。

## 3. 修订后的优先级

### P0：查询侧扩展（Query Expansion）——唯一能触及 60 题 `never_candidate` 的方向

- **做法**：不填 `seeds`，而是把描述性 query 改写成 N 条「实体名 + 关系」的候选查询（复用 `docs/实体识别与查询扩展_20260917.md` 与 `canon_names.json`），每条各自做语义检索，结果按 RRF 融合进现有通道。
- **为什么是它**：扩候选池深度（semantic_top 5→20）只换回 1 题，说明正解块不是「排在 20 名以内被截断」，而是**在向量空间里与原始 query 距离过远**。只有改变查询表示，才能改变召回面。
- **工程约束**：LLM 改写必须带超时（≤ 2s）、重试（1 次 + 退避）、失败降级为原查询（行为逐位不变）、开关默认 off、`--query-expansion on|off` 对照。

### P1：种子质量修正（针对 32 题「种子全错」）

- 实测种子含真阳的题通过率 0.708 vs 全错 0.475，差 23pt —— 种子质量确实是有效杠杆，但作用面是 32 题不是 5 题。
- 做法：把语义候选实体与 `link_detailed` 结果**合并重排**（而非仅在空集时补位）；泛词实体（`洞穴`/`海盗`/`无名者`/`孤独之歌`）继续走 `seed_gate` 拦截。

### P2：不要碰的

- `semantic_link_min` 绝对阈值（已证伪）。
- 融合层保底名额（作用面 27 题，且救援的是顶部块不是正解块）。
- `semantic_top` 扩深度（+1 题 / 负样本 +2 块，性价比不成立）。

### 验收闸门（沿用原计划，补一条）

- strict 195 → ≥ 210、inject 0.59 → ≥ 0.63；
- 负样本**失守条数**维持 7/53、**新增泄漏**维持 2 条（`解释一下相对论`、`红楼梦的作者是谁`）不允许增加；
  ——注意报「条数」而非「块数」：块数会把「1 条漏 5 块」和「5 条各漏 1 块」混为一谈。
- 新增：**必须报告 `never_candidate` 题数变化**（60 → 目标 ≤ 40），否则无法区分「真召回提升」与「排序层挪动」。

## 5. 口径与误差说明

- 「真阳实体」为启发式判定（题面 evidence 关键词 ∪ oracle full 块上下文），存在标注误差；
  但「`seeds` 为空 = 5 题」是**精确计数**，不受此影响 —— 本文核心推翻依据依赖的是这个硬数字。
- `diag_block_provenance` 的正解块主口径为 `full`（单块覆盖全部证据组）；`full` 为空时单列为
  `no_full_ceiling`（18 题），不并入任何失效模式，避免污染归因。
- 全部脚本为只读：`diag_block_provenance.py` 用实例级 spy 包住 `_fuse_channels` 并在结束时还原；
  `ab_semantic_depth.py` 只改运行期实例属性 `semantic_top`，同样在结束时还原。
