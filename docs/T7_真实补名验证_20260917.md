# T7 · 真实补名端到端验证（2026-09-17，闸门判定：不达标，不落地）

## 与「补名上界」的本质差别

| 实验 | 补名来源 | 300 题 strict | multi-hop |
|---|---|---|---|
| 上界（`ab_query_rewrite.py --oracle-names`） | **题集 ref 里的标准答案串** | **227（+28）** | 45% → 57.5% |
| 本实验（`ab_static_topup.py`） | **语料块内"描述↔实体名"共现**（13 条映射） | **196（+1）** | — |

## 实测（映射 13 题，逐条附语料依据）

- strict 195 → **196（+1）**；inject 177 → **175（−2）**；负样本不变（7/53 条、54 块）
- 映射题 13 题：**救回 1 题（R076 troll）**，砸掉 0 题
- **单题转化率 7.7%**（1/13），而上界口径 60 题转化 28 题（47%）

映射表（`t7_static_topup_map_20260917.json`）里 8 条 high confidence 全部基于块内直接共现：
Isolde、Kakania、Apeiron、Zeno、Six、Green Lake、ronium、Manus Vindictae。

## 为什么真实补名几乎不转化（根因，重要）

1. **上界实验的"补名"其实不是补名**：它拼的是 `ref` 整串（如
   "Charlotte O'Hagan（伦敦十字街女巫，前乌卢鲁运动会最年轻金牌得主）"），
   含**答案词本身**（职务/称号/事件名），直接命中答案块文本 → 近似把答案当查询。
   真实补名只能补"实体名"。
2. **multi-hop 失败题的答案大量不是实体名**：职务（standkeeper）、组织（重塑之手）、
   案件（雷米特杯失窃案）、矿物（ronium 虽可算实体）、名字（Pupa/六）——
   补实体名对"答案=非实体词"的题天然无效。
3. **补名后还要过完整链路**：即便补对实体名（Isolde/Kakania/Zeno），仍需图路/语义路
   把答案块送进 top-8 并覆盖证据组。补名只是激活了种子，不保证排序。
4. inject −2：补名改变了候选分布，挤掉了原本能覆盖证据组的块（与"往名额里塞信号"
   的历次实验同一机理）。

## 结论与路线图修正

- **T7 判定不达标（+1 vs 闸门 ≥+8），不落地**；`StaticMapIdentifier` 形态本身可用，
  但"模型离线读语料补实体名"的真实收益不足以支撑上线。
- **补名的适用面 ≈ "答案是具名实体"的题**；这类题在失败集中占比低。
- 要扩大收益，方向应转向**语料侧**（T9 document expansion：把"描述性问法"写进块文本，
  让块本身可被描述性查询命中），而不是查询侧继续补名——
  这是 Weller 2024"扩展的有效性取决于信息增量"在本项目的第二次验证。
- multi-hop 的剩余希望收敛到：T5（高层摘要）、T8（分解/摘要引导检索）、T9（语料侧扩展）。
