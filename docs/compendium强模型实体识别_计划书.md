## 3. 成败点：候选集怎么生成（本轮核心实测）

图谱有 **7033 个正名 / 8049 个可解析写法**，**塞不进 prompt**。
所以任何实现都必须先缩小到闭集候选。本轮测了三种候选生成器：

### 3.1 ❌ 向量候选（entity_index）—— 实测不可用

用 bge-m3 查 `entity_index`（7033 实体），看答案实体是否落在 top-N：

| N | native 覆盖 | 300_cn 覆盖 |
|---|---|---|
| top-5 | 1.1% | 5.1% |
| **top-20** | **3.3%** | 10.3% |
| top-50 | 7.6% | 15.4% |
| top-200 | 17.4% | 28.2% |

⇒ **完全不可行。** 与历史结论一致（`B4查询扩展实验`：bge-m3 语义链接最多 +1 题，
「向量认为错实体更像答案」）。**任何「向量召回候选 → 模型挑选」的设计都应直接放弃。**

### 3.2 ❌ 正典名单候选（plot 侧的形态）—— 覆盖不足

plot 侧用 `canon_names.json`（325 条，约 4652 字符）作名单。测其在 compendium 上的覆盖：

| native 题型 | 答案命中名单 |
|---|---|
| T1 | 41.7% |
| T1r | 61.4% |
| **T2** | **14.5%** |
| 300_cn | ~0.3% |

⇒ 名单是**加进 prompt 的候选上限**，覆盖不到一半 ⇒ 直接搬 plot 形态**注定低产**。

### 3.3 ✅ 图邻域候选 —— 覆盖 100%（T1/T1r），**推荐形态**

native 的 T1/T1r 题**题面点名实体 A**，答案 B 是 A 经某关系到达的另一端
⇒ B 应在 **A 的图邻域**里（不是向量近邻）。

| | native | 300_cn |
|---|---|---|
| 题面能链到实体（seed 非空） | 76.1% | 76.9% |
| **gold 落在 seed 邻域内（总体）** | **58.7%**（54/92） | 17.9% |
| ├ `[T1]` n=26 | **100%** | — |
| ├ `[T1r]` n=23 | **100%** | — |
| └ `[T2]` n=43 | 12% | — |
| 邻域大小（中位 / p90 / max） | **68 / 197 / 364** | 57 / 232 / 503 |

⇒ **T1/T1r（占 native 未命中 49/92 = 53%）的答案 100% 在题面实体的邻域内，
且邻域中位仅 68 个名字——完全放得进 prompt。**

#### 🔑 关键设计原则：候选只给**名字**，不给**边**

native 的题面是脚本用图谱关系串逐字生成的（`_gen_native_qa.py`），
若不慎把「候选实体 + 连接关系」一起喂给模型，模型只需做**字符串匹配**即可选中
——那是**作弊**，会把循环性污染当成能力（本轮在「关系加权」实验上刚踩过这个坑）。

**因此：prompt 里只放候选实体的名字列表（扁平闭集），不放任何边/关系/度数信息。**
模型必须靠**自己对这部作品的认知**从 68 个名字里挑。这既是诚实的，
也恰好对应真实用户场景（用户不会说图谱内部的关系词）。

## 4. 推荐架构

```
用户查询 q
   │
   ├─① 实体链接（现有 link()）：从 q 中取出实体 A          ← 复用，零改动
   │
   ├─② 候选生成（本计划新增）：
   │     candidates = names(neighbors(A))          # 图邻域，扁平名字表
   │     if |candidates| > CAP: 按 PPR 分截断到 CAP  # CAP≈200
   │     若 A 为空 → 不走本路线（保持现状）
   │
   ├─③ 强模型识别（离线优先）：
   │     输入：q + candidates（只要名字）
   │     输出：top-K 实体名（K≈3）
   │     白名单：输出必须 ∈ candidates 且能被 graph.resolve() → 否则丢弃
   │
   ├─④ 补名：q' = q + " " + 选中的实体名
   │
   └─⑤ 正常检索（现有 retrieve 路径，逐位不变）
```

**三条护栏（照搬 plot 侧设计，缺一不可）：**
1. **白名单**：输出必须能 `resolve()` 到图谱实体，解析不到就丢弃——绝不自由发挥。
2. **失败即不扩展**：异常 / 超时 / 空结果 / 开关关闭 ⇒ 返回**原查询**，行为逐位不变（零回归）。
3. **独立开关**：默认关闭，且**不复用**任何既有语义开关。

**在线 / 离线（成本与延迟的决定项）：**
- plot 侧实测：在线调用 **+1957 ms/次**，而检索 p50 仅 ~714 ms ⇒ **在线同步调用不可接受**。
- ⇒ **评测与生产都必须走「离线预生成映射 + 在线查表」**（`StaticMapIdentifier` 形态，
  在线零延迟）。代价：预生成只覆盖已知查询，**真实用户新问法不在覆盖内**。
- ⇒ 本计划**只承诺离线形态的收益**；在线形态需另行立项测延迟与成本。

## 5. 实施步骤（分阶段，每阶段带闸门；**本轮均不执行**）

### 阶段 0：治理裁决（**阻塞项，先做**）
- 产出：一份针对本路线的裁决记录，明确**是否允许触网关**、允许的范围（建议：仅离线、
  仅实体识别、**不得进入抽取/构图/评测路径**）、以及是否需要与裁决 C 并列登记。
- **闸门：未获裁决 ⇒ 不得进入阶段 1。**

### 阶段 1：候选生成器（**零网关、零模型**，可独立验证）
- 新增 `_gen_entity_candidates.py`（只读图谱）：对目标题集逐题输出 `{qid: [候选名...]}`。
- **闸门：native T1/T1r 覆盖 = 100%（本轮已实测 100%），均值邻域 ≤ CAP。**
- 这一步**完全不碰网关**，即使最终不做本路线也有独立价值（它量化了「答案是否可达」）。

### 阶段 2：离线识别（**本阶段才触网关**）
- 对阶段 1 的候选调强模型，产出映射文件。
- 冻结协议：**模型只看到 q + 候选名字表**（不含边、不含关系、不含证据）；
  返回 top-K；记录原始返回以便复核。
- **闸门：产出解析率（能过白名单）≥ 90%。**

### 阶段 3：离线回放评测
- 用映射做检索（`q' = q + names`），按**全量**口径出 `hit@6 / MRR / grounded`。
- **闸门（全部满足才可继续）：**
  - 主口径 `full/answerable` hit@6 **提升**；
  - `unanswerable` hit@6 **不得上升**（现 0.0096，这是本库最重要的安全底线）；
  - `grounded` 保持 **1.000**；
  - **零档自检**：空映射必须逐位复现 `eval_*_after_welds.json`。

### 阶段 4：决定是否接线
- 仅在阶段 3 全闸门通过、且**人工题集**（非 native）上也为正时，才讨论接入检索路径。
- 接入形态：默认关闭的开关 + `StaticMapIdentifier` 查表 + 三条护栏 + 单测。

## 6. 验收口径（本计划最容易被做坏的地方）

**必须用「全量」口径，禁止用 miss 子集投影报数。**
本项目本轮已连续两次踩到该坑：`max_edges` 在 miss 子集是 **+2.04pt**、全量是 **−1.02pt**；
关系加权在 miss 子集是 +6.40pt、真端到端是 +7.60pt 但**含循环性污染**。

| 项 | 要求 |
|---|---|
| 主口径 | `full / answerable`（300_cn 196 题、native 250 题），**全量** |
| 零档自检 | 空映射 ⇒ 与已存档基线**逐位相同**，否则整轮测量作废 |
| 安全底线 | `unanswerable` hit@6 **不升**、`grounded` = 1.000 |
| 双题集 | 两套都要报；**单集为正不算通过** |
| **循环性防护** | **native 的数字不得单独作为通过依据**（见 §7），必须同时报人工题集 |
| 逐题归因 | 报 up/down 的**具体题号**，不允许只报净值 |

## 8. 明确不做

1. **不做向量候选**（top-20 = 3.3%，已否证）。
2. **不把关系/边/度数放进 prompt**（会制造循环性作弊，R2）。
3. **不把自由发挥的实体名拼进查询**：本轮实测灰机盲猜补名在 native 是 **−8.80pt（1 涨 23 跌）**
   ——白名单与「失败即不扩展」是硬护栏，不是可选项。
4. **不用 miss 子集投影报数**（§6）。
5. **不改评测用例、不删题、不改检索代码去迎合指标**（铁律 #4）。
6. **不在抽取/构图路径上引入任何模型端点**（铁律 #1 的例外范围不得扩大）。
