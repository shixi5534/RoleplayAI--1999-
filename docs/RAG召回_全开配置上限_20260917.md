# RAG 召回 · 「全开配置」能达到多少（2026-09-17）

> 问题：假设 LLM 走云端强模型、所有加强功能都开，召回率能到多少？
> 结论：300 题 strict **65.0% → 75.7%（上界）**，inject **59.0% → 70.7%（上界）**；
> 上界是用标准答案名"补名"得到的（等于把答案喂给检索器），真实模型达不到，
> 按项目历史强模型命中率 62.7% 折算，现实预期约 **strict 72%**。

---

## 1. 分层实测（同一题集、同参数配对）

### 300 题集

| 配置 | strict | inject | 负样本 |
|---|---|---|---|
| 当前生产默认（加强功能全关） | 195（65.0%） | 177（59.0%） | 7/53 条、54 块 |
| + 补位重排 keep=5 | 199（66.3%） | 176（58.7%） | 不变 |
| + 救援兜底（min_semantic=2 / min_chapter=1） | 199（66.3%） | 176（58.7%） | 不变 |
| + **模型补名（100% 补对，上界）** | **227（75.7%）** | **212（70.7%）** | **不变** |

（最后一档已含补位重排与救援兜底；单独叠加救援兜底不改变结果——补名后语义块已足够强，
救援兜底保底的块变成冗余，这与它此前"无害但无效"的实测一致。）

### 全新 200 题（独立复核集）

| 配置 | strict | inject | 负样本 |
|---|---|---|---|
| 当前生产默认 | 147（73.5%） | 140（70.0%） | 7/53 条、54 块 |
| + 补位重排 keep=5 | 148（74.0%） | 140（70.0%） | 不变 |
| + **模型补名（100% 补对，上界）** | **156（78.0%）** | **151（75.5%）** | **不变** |

装置自检：两次运行的"补位重排基线"档分别复现 199 / 148，与此前独立评测逐位一致。

## 2. 这个 75.7% 是什么性质

**它是天花板，不是可交付指标。** 补名用的是题集 `ref` 字段里的标准答案名
（如把「阿派朗岛上以数字命名的少女」补成「… 37」）——等于把答案直接告诉检索器。
真实 LLM 只能猜，猜对率决定实际收益。

历史可比数据（项目代码 `plot_entity_expand.py` 的注释，实体识别任务实测）：
- 本地 qwen2.5:7b：**15.0%** 命中率 → 对应本轮实测的"多问法改写 0 收益"；
- 强模型：**62.7%** 命中率。

按 62.7% 线性折算（粗估，非线性关系，仅作量级参考）：

| 题集 | strict 上界 | 现实预期（粗估） |
|---|---|---|
| 300 题 | 227（75.7%） | ≈ 216（**72%**） |
| 新 200 题 | 156（78.0%） | ≈ 153（**76%**） |

## 3. 「全开」到底哪些能开、哪些不能

| 开关 | 是否开 | 依据 |
|---|---|---|
| `plot_rerank_topup_enabled`（keep=5） | ✅ 开 | 两份题集均非负（+4 / +1）；keep=3 在独立题集 −6，已弃用 |
| `plot_min_semantic_kept=2` / `plot_min_chapter_kept=1` | ✅ 可开 | 历史 300 题 +2、负样本不变；本组合下无额外贡献 |
| 模型补名 / 多问法改写 | ⚠️ 待验证 | 需有效 LLM key + 离线预生成；本地模型实测 0 收益 |
| `plot_semantic_link_min`（阈值） | ❌ 开不得 | 真阳余弦 p50 0.512 < 负样本 0.656，任何可用阈值会让 100% 负样本误链接 |
| `plot_semantic_top` 扩池 | ❌ 不开 | 全量实测 195→196 但 inject −6 |
| `plot_mention_per_entity` / `total_cap` 扩池 | ❌ 不开 | 全量实测 194（−1） |

## 4. 落地约束

- **延迟**：云端在线调用改写约 1–2 s/次，而检索 p50 仅 714 ms。
  必须走**离线预生成**「问法 → 补名」映射 + 在线查表（`StaticMapIdentifier`），
  否则在线同步调用不可接受。
- **收益口径**：真正提升的是 strict（并集口径）与 inject（装配口径）**同时**提升，
  这是与之前几版方案最大的区别（此前方案都是 strict 微涨、inject 下跌）。

## 5. 复现命令（项目根目录）

```
$env:ROLEPLAY_PLOT_RERANK_TOPUP_ENABLED='true'; $env:ROLEPLAY_PLOT_RERANK_TOPUP_KEEP='5'
$env:ROLEPLAY_PLOT_MIN_SEMANTIC_KEPT='2'; $env:ROLEPLAY_PLOT_MIN_CHAPTER_KEPT='1'
.venv/Scripts/python.exe -X utf8 scripts/ab_query_rewrite.py --oracle-names \
    --testset data/knowledge/_audit/rag_testset_300.json \
    --out data/knowledge/_audit/full_300_allon_rescue.json
```

产物：`full_300_allon.json`（补位+补名）、`full_300_allon_rescue.json`（再叠加救援兜底）、
`full_200_allon.json`（新题集）。
