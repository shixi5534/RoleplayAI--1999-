# T11 · 评测口径加固（抗灌水）· 已完成

## 动机

T5 实验暴露：`strict_pass` 判的是「返回块**并集的证据词覆盖**」，往结果里追加一个
「实体名列表」合成块就能**无条件**满足判定——实测把与题目无关的全局名表追加进结果，
strict 195→214（+19），而 inject **完全不动**。这类"指标灌水"会让任何"塞名词表"
的方案看起来有效。

## 实现（`scripts/eval_plot_rag.py`）

1. **新口径 `strict_pass_retrieved`**：证据覆盖只统计**检索通道返回的真实语料块**，
   排除 `metadata.synthetic == True` 的注入块；逐题落盘
   `strict_pass_retrieved` / `retrieved_covered`，汇总落
   `strict_pass_retrieved` / `strict_pass_retrieved_n`。
2. **硬约定**：任何实验或生产注入的合成块必须打 `metadata["synthetic"] = True`
   （已在 `ab_t5t8_summary.py` 落实），否则新口径识别不到它。
3. 与 `strict_pass` 的差 = **合成块贡献的"虚假通过"题数**。

## 回归核查（300 题，三档）

| 档 | strict（产品口径） | **retrieved（抗灌水）** | inject | 判定 |
|---|---|---|---|---|
| 基线 | 195 | **195** | 177 | 装置自检 ✓ |
| T5 摘要块追加（synthetic） | **217（+22）** | **195（±0）** | 177 | **灌水已被识别** |
| 补位重排 keep=5（已落地，默认关） | 199（+4） | **199（+4）** | 176 | **真实检索改善** ✓ |

结论：
- 新口径**精确**区分了两类"strict 上涨"——灌水的 +22 在 retrieved 下归零，
  补位重排的 +4 在两个口径下同时成立；
- **补位重排 keep=5 是目前唯一同时经得起两口径检验的产出**，其在抗灌水口径下
  仍有 +4（300 题）/ +1（新 200 题，早前测得），可继续走 T3 灰度。

## 验收规则修订（写入路线图）

> **铁律一**：任何"strict 上涨"必须同时满足 `strict_pass_retrieved` 不降，
> 否则视为灌水（合成块/名词表类）。
> **铁律二**：真改善必带动 `inject_pass`；inject 不动或下降的方案一律不落地
> （历史验证：补名上界 inject +36、补位重排 +1 = 真；T5、CE 精排 inject 不动/下降 = 假）。
> **铁律三**：合成块必须打 `synthetic=True`，否则属评测作弊。
