# RAG 召回优化 · 文献调研报告（2026-09-17）

> 围绕本项目当前四个实测结论做文献检索：①同义改写零收益/负收益；②multi-hop 是
> 洼地（两集一致 45–50%）；③"补实体名"上界 +12.5pt（multi-hop）而 inject 不涨；
> ④语义通道名额挤占（扩池/整体重排/改写都会压 inject）。
> 检索范围：ACL / EMNLP / EACL / ICLR / SIGIR / COLM / SemEval / ACM Computing
> Surveys / ACM TOIS / MDPI / arXiv（cs.IR·cs.CL）。

## 1. 最重要的一篇：它精确解释了我们为什么失败

**Weller et al., "When do Generative Query and Document Expansions Fail? A
Comprehensive Study Across Methods, Retrievers, and Datasets", EACL 2024 Findings**
（arXiv:2309.08541）

- 对 11 种扩展技术 × 12 个数据集 × 24 个检索器的系统研究：**扩展收益与检索器强度
  呈强负相关**——弱检索器受益，强检索器受害；
- 机理：扩展提供了额外信息（可能提升 recall），但**引入噪声，模糊了 top 相关文档
  的分辨**（引入假阳性）；
- 配方：检索器弱或语料与训练分布差异大时才用扩展，否则避免。

**对照本项目**：我们的语义通道（bge-m3）+ 五通道 RRF 已是较强的检索器，
qwen2.5:7b 的同义改写 = "没有信息增量的扩展" → 实测 strict 0 / inject −3，
与该论文的结论逐字吻合。**文献支持我们的"不落地"决定，这不是失败，是被验证的已知现象。**

它同时给出破局条件：扩展要有**信息增量**（新实体名/新概念），而不是措辞变化——
这正是"补名上界 +5/40"与"同义改写 +0"的差别所在。

## 2. 按项目问题分的文献地图

### 问题 A：multi-hop 洼地（45–50%，两集一致）

| 论文 | 出处 | 对本项目的意义 |
|---|---|---|
| Query Optimization Survey（四类操作：Expansion / Disambiguation / **Decomposition** / Abstraction，并按"单跳显式/多跳显式/单跳隐式/多跳隐式"映射方法） | arXiv:2412.17558 | multi-hop 的正统解法是**分解**，不是改写。我们的 60 题 never_candidate 大多是"多跳隐式"型 |
| Decomposing Complex Questions Makes Multi-Hop QA Easier（RERC 三阶段：分解→逐跳作答→汇总） | EMNLP 2021 Findings | 分解后的子问题各自检索，天然绕开"一个 query 覆盖不了多组证据"的困境 |
| Unsupervised Question Decomposition（ONUS，用海量网络问题无监督学分解） | EMNLP 2020 | 分解器可以无监督训练，不依赖标注 |
| Step-Back Prompting（先抽象出高层问题再检索，TimeQA +27%、MuSiQue +7%） | ICLR 2024 | 对"描述性问法"特别相关：把"海盗船上的歌手"抽象成"1.4 篇角色名对照"类查询，可能比同义改写信息量大 |
| GraphRAG（Edge et al., arXiv:2404.16130，微软）/ LightRAG | arXiv 2024 | 本项目就是剧情 GraphRAG；GraphRAG 论文明确：**KG 增益只在 multi-hop 且实体抽取质量高时成立**；LightRAG 双层检索（实体级/主题级）省一个量级 token |
| 自适应检索光谱：CRAG（零结果重试）→ FLARE（低信心触发）→ Self-RAG（ICLR 2024 Oral，reflection tokens）→ Adaptive-RAG（分类器按复杂度路由） | 2023–2025 | **生产模式共识：不要每问都加重处理**——按复杂度路由，只有困难题付出多路代价。正好匹配"multi-hop 才触发分解/改写" |

### 问题 B：描述性问法缺实体名（补名上界 +12.5pt）

| 论文 | 出处 | 对本项目的意义 |
|---|---|---|
| **Sci-ZSEL**（LLM 辅助、零样本实体链接） | arXiv:2609.00228 | 与我们的设想**几乎一致但更进一步**：①把别名生成**挪到实体侧离线做**（一次生成、跨语料复用，成本降一个量级）；②**本体感知漂移过滤**——LLM 生成的别名若与邻居实体更相似则丢弃（我们实体表里 story/time/Hey 这类脏别名，正是没做漂移过滤的结果）；③别名与人工 curated 同义词**合并使用效果最佳**（= 我们的别名桥 + LLM 别名） |
| D-STAR（source-free entity linking，问题生成 + 对比学习适配新实体域） | Information Processing & Letters (ScienceDirect) | 证明"给新实体生成问题-答案对来训练检索器"可行——即离线生成不只服务映射表，还能微调检索器 |
| 实体链接综述（JHU 学位论文） | JHU | 别名/昵称/缩写是 EL 的经典难点；"mention 与实体名零词面重叠"是最难档——我们的"以数字命名的少女→37"正是此类 |

### 问题 C：名额挤占与重排（扩池 −1、整体重排 inject −26）

| 论文 | 出处 | 对本项目的意义 |
|---|---|---|
| RRF 原始论文（Cormack et al.） | SIGIR 2009 | k=60 的设计：奖励**跨列表共识**而非单列表头名。我们的补位重排绕开名次，本质是给"单列表高余弦"豁免名额——文献上是"early fusion"与"late rerank"之争，我们实测补位胜过整体重排，与两阶段共识一致 |
| RAG-Fusion（Rackauckas） | arXiv 2024 | LLM 生成 3–5 个问法 + 多路检索 + RRF 聚合。**与用户设想完全同构**；其成立前提是改写有信息增量（见 Weller 2024） |
| **两阶段架构：bi-encoder 召回 top-100 → cross-encoder 精排 top-10**（BGE-Reranker-v2-m3 等；BEIR 上 rerank +5~7 NDCG，是 RAG 栈里单步收益最大的一步） | 2026 工程综述 + SemEval-2026 系统 | 关键数字：**候选池 k 在 30–50 达峰，k=500 普遍退化**——与我们"扩池无效（−1）"实测一致。正确姿势不是扩池，而是**加 cross-encoder 精排**；项目里 `plot_rerank.py`（bge-reranker）已存在未启用，这是下一步最高优先级 |
| RankGPT（Sun et al.）/ LRL（Ma et al.） | EMNLP 2023 | LLM listwise 重排（滑动窗口）；适合 top 10–20 的最终精排，成本高 |
| Attention Basin / Lost in the Middle（Liu et al. 2024；AttnRank） | ACL 2026 等 | LLM 对上下文首尾注意力高、中间低。我们 inject 口径"按名次填充、超预算即停"天然把关键证据挤到中间——**把最重要的块放开头/结尾**是零成本改动 |

## 3. 文献支持下的下一步排序（更新）

1. **启用并标定 bge-reranker 精排**（项目已有 `plot_rerank.py`，未开）：
   候选池 30–50 → rerank 取 top-6。文献口径这是 RAG 栈单步收益最大的一步，且与
   我们"名额挤占"的实测吻合——用精排代替"挪名额"。
2. **离线补名管线（实体侧）**：按 Sci-ZSEL 形态——用强模型对**实体**（而非查询）
   离线生成别名 → 漂移过滤（别名与邻居实体更相似则丢）→ 并入别名桥/静态映射表，
   在线零延迟。前置条件仍是有效 LLM key。
3. **multi-hop 分解**：只对 multi-hop 路由触发（Adaptive-RAG 模式），
   子问题各自检索后 RRF 汇合；不要对全部查询开改写（Weller 2024）。
4. **inject 口径的零成本改动**：装配顺序按"证据覆盖度"重排，把覆盖最关键证据组的
   块放首尾（Attention Basin）。
5. **暂缓**：进一步调融合权重/名额类微调——文献与我们的实测都表明这是低收益区。

## 5. 跨语言检索（CLIR）——我们的镜像场景：中文提问 × 英文 ASR 语料

| 论文 | 出处 | 对本项目的意义 |
|---|---|---|
| **What Drives Cross-lingual Ranking?**（四类干预系统评测：文档翻译 / 多语言 dense / 对比学习对齐 / cross-encoder 重排） | arXiv:2511.19324 | **结论：为 CLIR 专门训练的 dense 检索器稳定优于词面匹配；文档翻译几乎无增益**。多语言嵌入 + 学习式对齐是正道 → **背书我们的 bge-m3 路线，且"把语料翻译成中文"这类想法应打消** |
| **Smart Shuffling: Bridging the Translation Gap** | SIGIR 2020 | 关键机理：跨语言嵌入会把 query 词映射成目标语言的**相关词而非同义词**——"Adding related terms can be valuable, but must be mitigated by focusing on the starting query"。**这就是我们"改写漂移导致 0 收益"的文献级解释**：改写后的查询漂离原意，dense 检索在跨语言下对此更敏感 |
| Translate-Distill | arXiv:2401.04810 | 用 cross-encoder 蒸馏训练 CLIR dual-encoder——长期方向：把精排能力蒸馏进检索器，避免在线精排延迟 |
| ColBERT-X | arXiv:2201.08471 | XLM-R 迁移学习做 CLIR 的 late-interaction 路线 |
| TREC NeuCLIR track（英文 query × 中/波斯/俄语料） | TREC 2023– | 与我们"中文 query × 英文语料"互为镜像的公开评测轨道，有现成 best-practice 报告可对照 [待核实: 查 NeuCLIR overview 论文的具体系统配置] |

## 6. Graph-RAG 统一对比——**我们的架构与 HippoRAG 同构**

| 论文 | 出处 | 对本项目的意义 |
|---|---|---|
| **In-depth Analysis of Graph-based RAG in a Unified Framework**（12+ 方法统一实现与对比） | arXiv:2503.04338 | ① RAPTOR 与 **HippoRAG 是成本最低的 graph-RAG**（检索结构与朴素 RAG 相同，只换检索算子）；KGP/ToG 等走 LLM agent 循环的最贵且慢 30–70s；② **RAPTOR 分析：复杂 QA 显著依赖高层摘要信息（非叶节点）**；③ 明确结论：实体与关系信息对 multi-hop 是有价值的辅助信号 |
| **HippoRAG**（Gutiérrez et al. 2024；NeurIPS） | arXiv:2405.14831 [待核实: 查准确编号] | **PPR（个性化 PageRank）+ 知识图谱 + dense 相似度融合**——与我们"图传播 PPR + 语义向量 + RRF"**架构同构**。差距在融合方式：HippoRAG 用 PPR 分布**引导** dense 检索与排序，而非"按名次 RRF"。其 multi-hop 检索 recall@5 达 83–93%（HippoRAG 2 达 96.3%）。我们实测 multi-hop 只有 45–50%——同架构、差融合，这是最有指向性的改进方向 |
| GFM-RAG | arXiv:2502.01113 | multi-hop 检索横向对比表：HippoRAG > RAPTOR > BM25/Contriever；**LightRAG 在 multi-hop 上反而垫底**（HotpotQA R@2 38.8）→ 排除 LightRAG 方向；IRCoT（多步迭代检索-读-再检索）能提升所有单步方法 |
| RAPTOR（Sarthi et al. 2024） | arXiv:2401.18059 [待核实] | 递归摘要树：叶=原文块，上层=摘要。**对应我们的缺口：9021 块语料没有章节摘要节点**，而 multi-hop 证据经常是"跨章节的高层事实" |

## 7. ASR 转写检索（SDR）——语料是英文 ASR 转写的直接文献

| 论文 | 出处 | 对本项目的意义 |
|---|---|---|
| TREC SDR Track 系列（1997–2000 overview + Cambridge TREC-8 系统） | NIST / TREC | **检索性能对 ASR 词错误率的衰减相当平缓**：Cambridge 系统 WER 24.8% → AveP 55.08（人工转写 55.88，几乎无损），WER 66% 仍有可用检索 → **"ASR 噪声拖垮检索"的假设应降权**，瓶颈更可能在别处（实体名覆盖、块粒度） |
| Cambridge TREC-8 SDR 系统 | TREC-8 | 系统增强清单里收益最大的是 **document expansion（blind relevance feedback 扩展文档侧文本）**：55.29 vs 不用 41.47。与 doc2query/docT5query 同族的"**语料侧扩展**"——与查询侧扩展（Weller 2024 警告）相对，**文档侧扩展对强检索器同样有负风险，但在 ASR 语料上有独立验证的正收益**，值得做消融 |

## 8. RAG 评测方法学——我们的评测口径比 RAGAS 更可靠

| 论文 | 出处 | 对本项目的意义 |
|---|---|---|
| RAGAS（Es et al.） | arXiv:2309.15217 | 参考无标注评测（faithfulness / answer relevance / context precision / recall）的事实标准 |
| **Evaluation of RAG Metrics for QA in the Telecom Domain** | arXiv:2407.12873 | 对 RAGAS 指标的人工对齐审计：**只有 Faithfulness 与 Factual Correctness 与专家判断较一致**；Context Relevance 受上下文长度支配、Answer Relevance 依赖余弦"不可解释"（余弦做绝对指标的本体问题）。→ **印证我们坚持基于 ground-truth 证据组的严格口径 + oracle 天花板**，不要迁移到 RAGAS 式指标；也提示：我们缺"faithfulness"类的**生成侧**指标，检索改造完成后应补生成侧评测 |

## 9. 第二轮后的下一步排序（合并更新）

1. **对齐 HippoRAG 的融合方式**（同架构、差融合）：用 PPR 分布加权 dense 检索/排序，
   替代"按名次 RRF"对语义通道的扁平处理——文献 recall@5 83–96% vs 我们 45–50%，
   差距方向最明确。
2. **启用 bge-reranker 精排**（不变，仍是第一步）。
3. **实体侧离线补名 + 漂移过滤**（Sci-ZSEL 形态，不变）。
4. **章节摘要节点（RAPTOR 式）**：为 multi-hop 补"高层信息"入口。
5. **语料侧 document expansion 消融**（SDR 文献在 ASR 语料验证过的大收益项，
   与查询侧扩展的风险模型不同，需独立实测）。
6. **改写类方案全部降级为"信息增量"前提**：同义改写不做（Weller 2024 +
   Smart Shuffling 的漂移机理双重要求）。
