Recall 34%——但剧情层本来就是 bge-m3 + 多通道融合，那个归因是错的。**两条线的清单混在一起会互相误导。**

**佐证**：剧情层换成 bge-m3 后严格通过率 53.7% → 63.3%（+9.6pt），方法论已验证。

**做法（已勘察，见下方「勘察结论」）**

2. 配置层：`ROLEPLAY_EMBED_MODEL` 从 `nomic-embed-text` → `bge-m3`
   - ⚠️ **不要动 `ROLEPLAY_PLOT_EMBED_MODEL`**（剧情层已独立配 bge-m3，且索引按 1024 维建）
3. 全量重嵌入 6641 条（+ spoken 库）
4. 回归：跑 lore 侧评测脚本（`eval_rag_*.py` / `rag_huiji_eval_report`）

### ⚠️ L1 前提复核（2026-09-16 20:20）——两个发现推翻/修正了原动机

原动机（来自外部审查报告）：*"nomic 是英文单语模型，而 lore 库 6641 条全是中文 → 模型选错"*。

**发现 1：lore 库 92% 是英文，不是中文。**

| 语言构成（6641 条） | 条数 | 占比 |
|---|---:|---:|
| **英文为主** | **6117** | **92.1%** |
| 中文为主 | 424 | 6.4% |
| 中英混合 | 100 | 1.5% |

抽样可见：`are still here? You're new in town`、`I've committed many crimes` —— 都是 ASR 剧情转写。
只有 6.4%（424 条）是中文世界观条目（如「暴雨」「暴雨症候」「圣洛夫基金会」）。

⇒ **"库是中文所以 nomic 不适配"这个理由不成立**（对 92% 的内容，nomic 反而合适）。

**但换模型的理由依然存在，只是要换一个**：真正的理由是**查询侧是中文**——
中文用户问「暴雨是什么」，要在英文为主的库里检索，**需要跨语言对齐能力**，
而 nomic 是英文单语（剧情层已实证：切到 bge-m3 后严格通过率 +9.6pt）。
即：**不是"库是中文"，而是"问是中文、库是英文"**。

**发现 2：lore 库与剧情语料同源，存在架构冗余。**

| | 来源 |
|---|---|
| lore 库（734 个来源文件） | Top 全为 `BV1eo4y1u7aW_p43_公测全剧情…` |
| 剧情语料（9021 块） | Top BV 也是 `BV1eo4y1u7aW`（2801 块） |

两者是**同一批 B 站视频**，只是入库粒度不同：
- lore 库按视频 page 直接入库（6641 条）
- 剧情语料按章节重新切块（9021 块）+ 建图谱

⇒ 剧情图谱层已在更好的结构上覆盖了同一批内容（三通道 RRF + PPR + 篇章路由）。
**L1 若只是"把 lore 的 6641 条换模型重建"，收益可能被剧情层重复覆盖。**

### 修正后的三条路线（待用户决策）

| 路线 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **L1-a** 保持原方案 | lore 6641 条全量换 bge-m3 重建 | 改动直接、与剧情层同构 | 与剧情层内容重叠，收益可能有限 |
| **L1-b** 按语言分层 | 424 条中文世界观条目换 bge-m3；6117 条英文 ASR 保持或另行评估 | 精准、成本低 | 需评估"混合模型"的检索一致性 |
| **L1-c** 架构层评估 | 先分析 lore 层与剧情层的功能重叠度，决定 lore 层是否保留 / 缩减 / 下线 | 治本，省长期维护 | 需更大范围调研，暂不动手 |

**建议顺序**：先做 **L1-c 的重叠度分析**（只读诊断），再决定走 a 还是 b——
避免"重建半天、收益被重复覆盖"的无效投入。

## ✅ lore 层评测集补建（2026-09-16 20:45，用户要求）

## L2 · 接入 BGE-Reranker-zh 精排（P0）

**问题**
混合检索后直接取 `top_k`，**没有 Cross-Encoder 二次精排**。在向量分数无判别力时，线性加权接近随机排序。

**做法**
1. 候选池（`alpha=0.45`、候选 30）→ Reranker 打分 → 取 top-k
2. 模型候选：`BAAI/bge-reranker-v2-m3`（多语言，与 bge-m3 同族）或 `bge-reranker-base-zh`
3. 部署方式二选一：
   - 本地 `sentence-transformers` / `FlagEmbedding`（CPU 可跑，延迟 +50~150 ms）
   - Ollama（若有 rerank 支持）
4. 保留**降级路径**：reranker 不可用时回退到现有线性加权（与项目既有 fallback 风格一致）

**验收标准**
- 同一批查询：top-k 内的相关块占比提升（precision ↑）
- 延迟 p95 增幅可接受（参考剧情层 p95 = 730 ms）
- 有 reranker 不可用的降级验证

## L4 · `top_k` 3 → 5（P1）

**问题**：`top_k=3` 本质是"用少注入代替阈值过滤"，牺牲召回换精度。

**前置条件**：**必须先有 L2 精排**，否则扩大 top_k 只会注入更多无关内容。

**做法**：`top_k` 3 → 5，观察 recall 与 precision 的权衡曲线（可做 3/4/5/6 扫描）。

## L5 · BM25 中文切分（P1）

**问题**：中文按单字切分，"暴雨"与"暴力"都含"暴"，IDF 对常用字无区分度。

**做法**：改用 jieba 分词或 bigram；对剧情/世界观专名建立自定义词典（可复用 `huiji_lexicon.json` 的 913 条中文名 + 图谱别名）。

**验收**：含中文专名的查询，BM25 通道命中率提升。
