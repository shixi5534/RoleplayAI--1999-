## 四、最令人意外的发现：剧情图谱 >> lore 向量检索

这个项目的**剧情图谱层（PlotGraph）工程深度远超 lore 向量检索**，形成了明显的"长短腿"：

### 剧情图谱层（做得好的部分）

| 能力 | 实现 | 实测效果 |
|---|---|---|
| 跨语言语义 | bge-m3 多语言嵌入，独立于全局 nomic | 300 题严格通过率 **53.7% → 63.3%（+9.6pt）** |
| 三通道融合 | 边证据 + 实体提及 + 词法 BM25，RRF(k=3) | 解决了分数量纲不可比问题 |
| 别名可信度分层 | 人工表别名=可信，抽取别名降权×0.25 | 修好真实对话问题 A1 7/7 |
| 篇章路由 | 用户点名篇章时缩小 BM25 候选池 | 唯一能救"洞穴的囚徒篇里海盗船上的歌手是谁"这类题 |
| 噪声过滤 | 代词/称谓/泛词三张黑名单 | 防 ASR 残句污染图谱 |
| 评测体系 | 300 题标准集（factoid 200/multi-hop 60/reasoning 30/temporal 10） | 每个参数都有消融数据 |
| PPR 调优 | max_iter=20（实测 20 与 40 质量完全相同，p95 从 298ms→178ms） | 用数据砍延迟 |

**剧情图谱的严格通过率从最初 42% 优化到 63.3%，MRR 0.337→0.386，是整个系统里调优最充分的模块。**

### lore 向量检索（短板部分）

| 问题 | 证据 |
|---|---|
| **嵌入器是英文单语模型** | nomic-embed-text 对中文语义理解弱，而 lore 库 6641 条全是中文 |
| **代码自承认无判别力** | 注释原文："相关/无关两组原始余弦完全重叠（0.702 vs 0.695）" |
| **没有 Cross-Encoder Reranker** | 混合检索后直接取 top_k，没有二次精排 |

## 五、核心技术债（按严重程度排序）

### 1.【致命】lore 向量检索嵌入器选错了

nomic-embed-text 是**英文单语**模型，你的 lore 库 6641 条全是中文世界观/角色设定。代码里已经实测确认余弦分数无判别力（0.702 vs 0.695）。

**剧情层已经验证了 bge-m3 的效果（+9.6pt），但全局嵌入器还停留在 nomic。** 把 lore 库换成 bge-m3 重建，是当前 ROI 最高的单一优化。

### 2.【致命】没有 Reranker

30 条候选 → 线性加权排序 → 取 3 条。在向量分数无判别力的情况下，线性加权等于瞎排。加一个 BGE-Reranker-zh，30→重排→取 5，召回和精度会同时提升。

### 3.【严重】纯 JSON 存储，启动全量加载

- lore 78MB + graph 41MB + plot_index 60MB + plot_corpus 10MB ≈ **190MB JSON**
- 启动时 `json.load` 全量反序列化，Python 对象内存翻 3-5 倍（**500MB-1GB 内存**）
- 并发读写靠 `threading.RLock` 硬扛
- 每次 add/remove 都整命名空间重写落盘（写放大严重）

**应该迁移到 SQLite（文本+元数据）+ numpy（向量），或直接用 ChromaDB/Qdrant。**

### 4.【严重】plot_graph.py 单文件 2027 行

虽然结构还算清晰（PlotGraphRetriever 类 + 辅助函数），但实体挖掘、别名表、噪声救援、PPR、三通道融合、篇章路由、语义通道全塞在一个文件里。改一处怕崩全局，单测无法隔离。

**应该拆成：entity_linker.py / ppr_engine.py / channel_fusion.py / chapter_router.py / semantic_channel.py / noise_filter.py。**

### 5.【中等】项目卫生极差

- `scripts/` 100+ 个脚本，其中 43 个 `apply_missing_p*.py`（p1-p43）是一次性批量修复脚本，用完没删
- 根目录：`repro.py` / `repro2.py` / `repro3.py` / `_shuzhi_extract.txt` / `_tmp_pron_edges.txt`
- 4 个 pytest 临时目录：`.pytest_tmp` / `.pytest_tmp2` / `.pytest_tmp3` / `tmp_pytest`
- `scripts/` 里混着 `__pycache__`（.pyc 文件提交到了源码树）
- `desktop/src/main/index.js.bak` + `_writetest.tmp`
- 大量 `*.bak` / `*.bak_voicelore` / `*.bak_18` / `*.bak_acceptance` 数据备份

### 6.【中等】lore 知识图谱建了但没启用

`graph_wu_ming_zhe.json` 有 3608 条边、41MB，说明花了大量 LLM 调用建图。但 `.env` 里没有 `ROLEPLAY_GRAPH_ENABLED=true`，默认关闭。**这部分投入目前是沉没成本。**

### 7.【中等】前端 redesign.html 116KB 但主入口还是 index.html 23KB

说明做了 UI 重设计，但没切换到主入口。两套前端并存，维护成本翻倍。

## 六、做得非常好的地方（不能只骂不夸）

1. **配置即文档**：`config.py` 每个参数都有实测消融注释，比如 `plot_ppr_max_iter=20` 注释里写了"300 题实测 20 与 40 质量完全相同，p95 从 298ms 降到 178ms"。这种注释比任何文档都有价值。

2. **降级链完整**：Ollama 不可用→Hashing 兜底；嵌入器切换→自动重建向量；图谱文件缺失→静默回退纯向量；联网失败→不影响本轮回复。每一层都有 fallback。

3. **提示词工程精细**：`persona_prompt.py` 里 RAG 上下文块的使用守则写了 8 条，包括"资料是记忆碎片不是参考资料""修辞之后必须带出至少一个具体事实""资料没提到的宁可留白也不补全"。这是经过幻觉问题踩坑后的经验沉淀。

4. **会话级并发锁**：`_session_lock` 保证同一会话"读历史→生成→落盘"串行，避免并发交错轮次。超过 500 会话时清理空闲锁，防内存泄漏。

5. **日志脱敏**：`openai_like.py` 里 `_redact` 正则把 Authorization/sk-/api_key 全部替换为 `***`，避免凭据泄漏到日志。

6. **增量摘要**：历史摘要有游标，只压缩新增轮次，不重复烧 token。

7. **测试覆盖广**：49 个测试文件覆盖 API/编排/RAG/图谱/语音/QQ 渠道/QA 回归，且有 `test_plotrag_*` 一整套 M0-M12 迭代测试。
