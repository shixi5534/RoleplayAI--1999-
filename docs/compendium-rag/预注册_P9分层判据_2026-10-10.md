## 1. 命题与既有证据

**命题**：把 L2.3 / L4.3 从「单一检索层硬门槛」改为**分层**——检索层放宽到 **≤0.08**，
答案层收紧到 **≤0.03**。用户原话：「①改判据是自欺欺人……判据与机制同源」——被否决的是
**放宽检索层判据去迁就机制**（「任一 seed」路线），**不是**「把同一现象在生成侧另立一门测量」。

支撑本分层的既有实测（全部为仓库内既有产物，未重跑）：

| 证据 | 读数 | 出处 |
| --- | --- | --- |
| 17 个「角色域隔离」机制臂全量判负 | 最好档 `M3_w1.0` = L2.3 0.0578 / L4.3 0.0506，仍双越线，且掉 23 题 | `reports/p8_roleiso_shadow.json` |
| 机制地板（首 seed 判据下不可修部分） | **0.0356**（8/225） > 门槛 0.03 | P8 报告 §2.3 + 交接档 §6 |
| 泄漏块的 44.4% 就是 gold 本身 | `gold_share_of_cross = 0.4443` | 同上 |
| 泛称角色名路线实测零支持 | 漏题 **0/35**、对照 **0/190** | `reports/p9_entity_census.md`（本轮新增） |
| 同角色多实体归并可解释量 | 仅 **3/35** 题（lift 16.2 但样本小） | 同上 |
| 近名种子碰撞启发式 | lift **0.905** ⇒ **无判别力，判负** | 同上 |
| 未落名 speakers（角色边界标注路线） | lift **3.88** ⇒ 相关，**未证因果** | 同上 |

**结论**：检索层在现判据下已被证明**够不到 0.03**（地板 0.0356），而实体层两条路线加起来
最多解释 3/35 题。分层不是偷懒，是把「泄漏是否真的伤害了最终回答」这一实际关切搬到一个
**测得到、也修得动**的位置上。

## 2. 口径定义（可重放，逐字固定）

### 2.1 检索层（沿用原实现，**只换阈值**）

- **L2.3-检索**：判据源 `scripts/audit_l2.py:258-276 leak_check`，**语义与分母一字不动**——
  角色域题 ⟺ `seeds[0]` 实体 `type=="角色"`；泄漏 ⟺ top-10 中 `category=="character"`
  且「正文+speakers」不含该角色任一名号的块。分母 = 当期角色域题数（r11 口径为 **225**）。
  新阈值 **≤0.08**（原 ≤0.03 转为「历史层」，见 §4）。
- **L4.3-检索**：判据源 `scripts/audit_l4.py:498-545 mode_privacy`，锚点 =
  `data/knowledge/_audit/l4_privacy_gold.json`（**80** 条独家事实），题面**只点名提问者**
  （不点名锚点主人，否则检索命中本人篇章是正确行为、口径会自证），锚点块进 top-6 记一次泄漏；
  提问者姓名/别名已出现在锚点原文者判为可公开、**移出分母**（r11：80 − 1 = **79**）。
  新阈值 **≤0.08**（原 ≤0.02 转历史层）。

⚠ **分母规则**：分母只允许由上述判据自身的过滤产生，**禁止**为了达标挑分母。
`0.08` 相对 `0.0356` 地板是**可达**区间，因此本层仍是一个真门槛，不是安慰剂。

### 2.2 答案层（新造测量，**复用现成装置扩样**）

- **L2.3-答案 / L4.3-答案**：判「生成后的回答是否把他人私密当己知、是否转述跨角色锚点」。
  装置直接**扩样既有 L5.3 confuse**（`scripts/audit_adv.py:308 mode_confuse`）：
  把 B 的私密锚点块塞进 A 的上下文 → 问 A 关于 B 该事实 → 双盲判「认领」（`appropriation`）。
  - 现值：n=**30**、`appropriation`=**0**、rate **0.0**、门槛 ≤0.10（`reports/audit_adv_confuse.json`，r11 冻结件）。
  - 扩样：题量从 30 扩到与 privacy gold **同规模 80 锚点**，批次文件与判分件走
    `data/knowledge/_audit/l5_confuse/`（`cf_bNN.json` + `answer_instructions.md` +
    `judge_instructions.md` + `hidden_gold.json`）→ `l5_confuse_answers/` → `l5_confuse_judge/`。
  - 被试回答由**盲子代理**在截断上下文内生成（与 P4/P5 同法），**零云端**，不调 LLM 网关。
  - 阈值 **≤0.03**，判据指令文件开工前冻结并记 sha，判分人**不得**看到检索层读数。

### 2.3 两条禁令（防自证）

1. **同源禁令**：任何降权/过滤判据不得与 L2.3/L4.3 判据同源。P8 已把此条机制化
   （`compendium_rag_p8_roleiso_shadow.py` 的 `TAUTOLOGICAL={"M3f_w1.0"}` 强制判负），本册沿用。
2. **不得互推**：confuse 是**人为注入他人锚点块**的强设定，与真实检索泄漏不同分布。
   答案层达标**不等于**检索层泄漏已消失，反之亦然；两门各自独立报数，不许合并成一句结论。

## 4. 报告格式（记分卡怎么变）

- **两列并排**：每条 gate 同时报「原口径（历史层）」与「新分层口径」，谁都不许盖掉谁。
- **原口径 FAIL 不因新口径达标而改判**；改判只发生在原口径自身读数真的达标时（D3 精神）。
- 层分重算规则先登记后生效：`L2` 权重 25 / `L4` 权重 30 不变；分层后**检索层与答案层各占该 gate 的一半**，
  避免「一门变宽就涨分」；具体重算式在实现 PR 里给出并回填本册。
- 等级不承诺：本轮只报实测影响，禁止「预计可达 B」。
