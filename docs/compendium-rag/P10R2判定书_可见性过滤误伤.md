## 1. 一句话

**R2 的两种可见性形态（按名字、按章节在场）都判负**：
在已跑满的 300cn 集上 Δ MRR@10 = **−0.1296（strict，角色域口径；全集 −0.1012）/ −0.1115（scene）**，
是回退线 0.02 的 **5.1–6.5 倍**；机制上误伤全部来自**转述型金标**
（占角色域题的 **56.2%**，那一批题的 Δ = **−0.2424**）。
这不是"要不要小心点实现"的问题，是**可见性键选错了**：本语料的私密信息大量存在于
"别人转述 A"的块里，名字与章节两种代理键都标不住它。

## 3. 三条推论（按证据强度排序）

1. **strict 不可落地**，且不是"参数没调好"：56% 的角色域题其金标块本来就是转述块，
   这一档过滤规则与语料结构对撞。
2. **scene 也救不回来**（只比 strict 好 0.018）。原因是转述块常常整章都不提主体
   ——"该章出现过"这个松键在数据里不成立，不是设计上没想到。
3. 与 P3 的角色域影子实验同向且更严：P3 实测 owners 尺子把 **17–30%** 的转述 gold 算成跨域
   （`project-p3-rolefilter-shadow-verdict`），这里换个指标、换套题集，量到 **56%** 与 −0.24。
   **两次独立判负，方向一致**，所以不该再试第三种代理键。

## 4. 那么 `N_retrieval` 这一格怎么办

不能靠可见性边把 21 条压到 ≤15，理由是上面的代价 measured；
也不该靠调阈值或改分母（纪律禁止）。剩下的只有一条**口径裁决**，需要你来定：

- 现在这一格记的是"检索命中了归属他人的私密块"。但归属是用**独占块**定义出来的
  （`compendium_rag_p9_cbi_testset.py:165` 双向独占选块），于是这一格
  **可被任何同类过滤器清零 ⇒ 不可证伪**（详见 `owner_shadow.md` 与本册 §R2）。
- 可落地的替代不是"放宽到 5%"，而是把判据改成有真语义的那一句：
  **「检索到的他人私密块，且该块对当前视角 A 不可见」才算泄漏**，
  其中"不可见"由**逐条隐私标注**决定，而不是由名字/章节代理决定。
  这条要写图就先要标注产能 —— 而本项目**零云端**，500 条样本的人工标注都要你来标，
  全语料 3589 个可归属块逐块隐私标注不现实。
- 因此我建议：这一格先**降级为能力读数、不参与达标**（保持实测值 21/500 如实报），
  把 R2 的写图预算转投两个有实测收益的地方：
  ①答案层拒答话术（§R1，3 条 soft 且不可重复，成本 0 写图）；
  ②题集 i 五臂与 L2.3/L4.3 的结构性不可达收口。
  **这是建议，不是裁决**，改判据要你先点头并像字面/对照那次一样先登记再跑。
