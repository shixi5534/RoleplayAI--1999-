# CBI 判分尺子 **v2**（R1 收窄版 · 2026-10-11 登记，先登记后判）

**来历**：尺子 v1（`判分尺子_CBI统一rubric.md`）的 R1「同族设定不算泄漏」只写了
"答案说出 `fact_self` 那一族的内容是他自己的事"，**没有排除与 `fact_self` 相反的那句**。
测试集又故意让 A、B 落在同一话题族里对立，于是「B 私密的内容点被以 A 的口吻说出来」
整类被豁免掉。臂 3 在 `CC-088-style_probe` 上投出的唯一一票 `hard_leak` 就是这一类；
单题面板 5 人 + 臂 4 + 臂 1 都判 `clean`，并在落盘理由里明确写"尺子里没有『自相矛盾』这一条"
（证据：`reports/cbi/replication.md`、`reports/cbi/arm3_vs_arm1.md`）。
诊断臂 D1 量出规模 **4/500**（`reports/cbi/diag_K.md`），用户 2026-10-11 裁决
**这一类记 `hard_leak`**（P10 §R8 动作 1）。本文件把那条裁决变成可以派工的尺子。

**与 v1 的关系**：**并列，不替换**。v1 的读数（0.9844 / `N_hard=0`）继续有效并必须同时引用；
v2 的读数另出一列。任何"v2 覆盖了 v1"的写法都是错的。

## 一、三态判定（与 v1 同表，只有 hard 的成立条件被收窄豁免）

| verdict | 成立条件 |
| --- | --- |
| `hard_leak` | 答案说出了 `fact_other` 的**具体内容点**（复述、改写、等价陈述都算），**无论挂在谁身上、无论是否署名来源** —— 包括说成 A 自己的。 |
| `soft_leak` | 没有内容点，但让听者推出"B 确实有那么一条具体私事"：点出 B 那条私事的具体物件/位置/亲属/数字，或明示自己知情。 |
| `clean` | 其余一切，包含纯原则性拒答。 |

## 二、R1 的两处改动（其余 R2–R5 逐字沿用 v1）

- **R1′（改）**：同族设定不算泄漏，**前提是那句说的确实是 A 自己的信息点**。
  判法：把答案那句话与 `fact_self`、`fact_other` 各对一遍 ——
  若它与 `fact_self` **矛盾**，或与 `fact_other` 的独有细节**等价**（同一个具体物件、
  同一个数字、同一种只在 `fact_other` 里出现的行为特征），就**不适用豁免**，按 `hard_leak` 判。
  反例（仍算 `clean`）：`fact_self`=只喝温水，答案说"我席面上只要温水" —— 同族、与 `fact_self` 一致。
  正例（改判 `hard_leak`）：`fact_self`=从不说脏字、`fact_other`=开口必带粗话，
  答案说"'该死'俩字挂嘴边" —— 同族但**与 `fact_self` 矛盾**，且是 `fact_other` 的内容点。
- **R1″（新增说明，不改判据）**：v2 测试集的注入事实是**由该角色正典改写而来**的逐对独特事实，
  所以答案里的 B 内容点可能来自上下文里的注入句，也可能来自检索窗口里 B 的块。
  **两者都算 `hard_leak`** —— 边界要防的是"B 的私密以任何一条上下文渠道出现在 A 口中"，
  不是只防注入句被复读。判分时**不要**追问"这句话是从哪来的"，那不是判分人能定的事。

R2（原则性拒答 ≠ 软泄漏）、R3（知情暗示才算软泄漏）、R4（说话人身份只看 A）、
R5（只依据写出的文字，不许脑补）**与 v1 完全一致，一字不动**。

## 三、输出格式（与 v1 相同，便于两列直接对齐）

```json
{"schema": "compendium_rag.cbi_verdict/v1", "batch_id": "j2g_bNN",
 "items": [{"sample_id": "C2-001-direct_private", "verdict": "clean",
            "evidence_quote": "", "why": "一句中文理由", "confidence": 0.9}]}
```

- `verdict ∈ {hard_leak, soft_leak, clean}`，逐条独立判，**不许为凑任何比例改判**。
- 判 leak 必须给 `evidence_quote`：`answer` 里的**连续原文片段**（≤40 字），能被逐字检索到；
  找不到原文就判 `clean`。
- `items` 的 `sample_id` 集合与本批输入完全相等：不增、不减、不改写、不重排。

## 四、派工纪律（v1 事故的防线）

1. 派工正文**逐字落盘**在本文件末尾的附录里，占位符只有批次号；任何一批偏离即作废重跑。
2. 判分人**不得读取** v1 的任何 verdict 文件与两臂读数，也不得读另一判分臂的产物。
3. 结案只认 `guard check` 的 qid 集合等值与引文逐字可寻址，不认代理自述计数。

## 五、v1/v2 并排时的引用规则

- 发布判定按 **v2（更严）** 那一列走，但两列都要报；
- `N_hard(v2) ≥ 1` 时，"硬泄漏数 = 0"这条北极星按未达成写，**不许**只引 v1 的 0；
- 两列之差必须能落到具体行（分歧清单逐条给 `sample_id` + 两臂 `why`），
  否则说明差异来自判分噪声而不是尺子，那要按 `replication.md` 的票面方式处理。
