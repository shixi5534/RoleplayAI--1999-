**21 条里有 16 条（76%）集中在 multi_role 一类**，而该类只占样本的 20%。
multi_role 的题面结构是"这场景里 B 和 C 都在，请把 A 本人的情况讲清楚"——
检索按语义把 B/C 的章节捞进来本来就是**正确行为**，记成泄漏是因为子标准按"命中他人私密块"计。
这一条不是要去调阈值（那是 `feedback-fix-data-not-metrics` 禁的事），
而是要在 P10 用 **owner/visibility 边标注 + Canon/Fandom 双轨**给它真正的访问控制语义——
届时"检索到但不可见"才等价于缺陷，现在它只是能力读数。

literal 口径下 `direct_private 0.66 / multi_turn 0.65 / inductive 0.62` 明显高于
`style_probe 0.35 / multi_role 0.32`，前三类正是"题面把 B 点名了"的那几类。
**你目标声明里的「当前 0.84」与字面口径上限 0.844 几乎相等**，据此推断那个基线量的不是边界失守，
而是"检索能否找到被点名角色的章节"。（用户 2026-10-10 已裁决：验收按 control 口径。）

### 2.3 关于 κ（必须说清的一条）

规格要「LLM Judge 与人工一致性 κ ≥ 0.80」。**机判对机判给不出这个数**：500 条里机判 497 clean + 3 soft，
若拿第二遍机判当"人工"，其分布与第一遍高度同源，κ 会虚高；而探针 pass 2 曾出现全 clean 的单一类别，
那时期望一致率 = 观测一致率 ⇒ **κ = 0 属退化，不代表一致性差**。所以人工那一臂只能由人来出，
量具已备好：`scripts/cbi_spotcheck.py` → `reports/cbi/spotcheck_sheet.md`（52 行 = SEED=42 分层随机 50 条 +
全部机判非 clean 的争议条，其中 1 条已在随机样本内）。

## 4. 要拿到"完全发布"还需要什么

1. **人标 50 条随机行** ⇒ 补上 κ 这一格（本轮唯一还缺的闸门）。
2. **把 N_retrieval 从 21 压到 ≤15**，且要压得有意义 ⇒ 只能动检索侧的访问控制：
   `owner`/`visibility` 边标注 + Canon/Fandom 双轨隔离（预注册册 §5 的 B1–B4）。
   **这些全是写图操作，需逐次批准**（task #4 的 8 条 `merge_entities`、task #5 的边界标注干预实验都还挂着）。
   压不下去的替代路径是承认该子标准在当前量具下把"检索能力"记成了缺陷——那要改的是判据定义，
   而改判据必须先像你 2026-10-10 的裁决那样**先分口径**，不是把 3% 改成 5%。
3. **软泄漏属话术层，不动图就能收敛**：3 条全是"把回避锚在 B 的话题域上"。
   system prompt 里加一句"拒答时不要点出对方的姓名与话题落点"即可；
   这是**唯一便宜的改进**，但它救不了检索子标准。
4. **裸能力对照臂仍未跑**：答案臂 prompt 里已含边界指令，所以 0.9844 量的是"带规则部署时的行为"，
   不是模型裸能力。要拆出规则本身值多少分，需再开一波不带指令的作答。

## 5. 量具与过程的自陈（含我自己犯的错）

1. **测试集 v1 选对逻辑错**：按共现次数取 top 对，可用对只剩 36/100——最同场的对
   恰恰最没有"只提 B 不提 A"的块，选择性约束与判据互相打架。
2. **v2 抽到编号群演与占位名**：`210 × 基金会职员Ⅰ` 里给群演注入"无酒不欢"不构成私密事实
   （P9① 实测 146 簇里 136 是编号群演）。加具名过滤才对。
3. **小样本外推错过两次**：100 条对照点测 0.010 被我说成"上限 0.997"，中途 53 行又变 0.19，
   500 行定稿 0.042。**这个量具上小样本外推不可用**。
4. **判分尺子中途换过**（探针 pass 1 的 5 批缺规则 2）⇒ 探针那两臂的差完全由我的操作造成。
   本轮全量 25 批因此**先把 rubric 落盘、再派工**，25 批共用同一把尺，且派工 prompt 逐字相同。
5. **计算器一度造出不可达的"发布"档**：MRR/Faithfulness 两格塞的是说明文字，
   `all(v is True)` 永不成立——与本项目吃过教训的"数学上不可达闸门"同类，已改真布尔。
6. **后台任务退出码被我自己盖掉过一次**（命令尾巴接了 `tail`，崩掉报成 exit 0），
   已改为看产物行数 + 心跳判定；本轮所有波次一律以 `check` 的 qid 集合相等为完成判据。
7. **子代理自报计数不可信**：答案波里有代理报"7 条引回自身 + 7 条拒答他人"（=14 > 10），
   算术上不可能。实际校验 50/50 批全齐，判分 25/25 批全齐，**没有任何一批是靠自述收下的**。
8. **`--protect data/knowledge` 把治理脚本拖死过一次**（该目录 881 MB，plan 逐文件哈希），
   已改为只保护 `graph.json`；写面越界两波均报 0 处。
9. **Wilson 区间偏乐观**：500 条只覆盖 **63 个不同的 A 侧角色**（B 侧 62），
   同角色的 5 题共享上下文与同一对注入陈述，不满足 i.i.d.。表里的 [0.028, 0.063] 是按独立算的，
   真实抽样噪声更大——这不影响"4.2% > 3%"的结论（点估计已越线），但别拿它当严格界。
   详见 `P10修复计划_CBI收口.md` §R5-2。
