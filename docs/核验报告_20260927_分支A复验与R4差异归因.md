## 3. R4 裸 +3 不可复现：发现 → 排除 → 根因

**发现**：冷启动 eval300（同脚本/同测试集/同 top-k）= 156/196 = 0.7959，与冻结 after_r3 **逐题零差异（600 行×2 模式）**；与冻结 after_r4 的差异恰为 R163/R248/R299 三题 True→False。

**排除项**：
- 图被换？——SHA 三次复核均为 R4 锁定值 c021f0a0bc7a0dce。✗
- 持久索引陈旧？——索引 mtime 12:03/12:06（R1+R2 时代，R3/R4 后未重建）属实，但**重建索引后冷跑仍 156**（且 chunk_index 重建结果与 Sep 25 备份逐字节相同——chunk 层全程未变）。✗ 非主因
- 机器负载/非确定性？——R4 时代评测 36.4s/题 vs 今日 1.8-2.4s/题（当时带载属实）但三次冷跑逐题全等（0/600 翻题），确定性成立。✗

**根因（受控实验确认）**：`retriever.py:300` 对 alias_index 键按长度降序排序，Python 稳定排序使**同长键 tie-break 取决于字典插入序**；R4 时代评测/采集跑在 Applier 落盘后的**暖进程**里（内存别名索引插入序）与冷重建自 graph.json 的插入序不同 → 3 道边界题翻转。交接文档"模拟保真度缺口"一节的原怀疑坐实，且**双向生效**：R4 的 +3 与冻结 collect 的重排 0.8673 都是暖态测量。

**时间线**：相遇测试 11:14（R1+R2 图）→ 索引构建 12:03/12:06 → R3 落盘 12:59（未重建）→ R4 应用 14:06（未重建）→ R4 暖评测/采集 → 16:18 提交并锁定 BASELINE_v4 → 今日一切冷评测 156/196。
