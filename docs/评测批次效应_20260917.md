# 评测管线的「批次态」效应：绝对指标会漂移 6.7 pt

- 发现时间：2026-09-17 10:26
- 触发：验证「查询侧实体扩展」组件时，同一输入两次运行给出 0.6900 vs 0.6167，
  逐题查证发现 **query 文本完全相同、资产指纹相同**，但 44 题判定不同

## 一、现象

把当天所有全量评测按 `meta.elapsed_s` 排序，出现**两个稳定的态**：

| 态 | elapsed | 判据 | clean 题集 inject | expanded 题集 inject |
|---|---|---:|---:|---:|
| **慢态** | 154 ~ 205 s | ≥120 s | **0.6200** | **0.6900** |
| **快态** | 22 ~ 63 s | <100 s | **0.5533** | **0.6167** |

| 运行 | inject | elapsed | 态 |
|---|---:|---:|---|
| base_1 / base_2 / base_3 | 0.6200 | 170.9 / 199.0 / 169.0 | 慢 |
| entoff_1 | 0.6200 | 202.4 | 慢 |
| expand_1 | 0.6900 | 154.1 | 慢 |
| expand_hm_1 | 0.6600 | 204.6 | 慢 |
| expand_high_1 | 0.6233 | 204.3 | 慢 |
| lexalways_1 | 0.6100 | 186.4 | 慢 |
| linkmin50_1 | 0.6200 | 191.4 | 慢 |
| seed_base_1 / seed_base_7 | **0.5533** | 63.3 / 22.6 | 快 |
| seed_exp_1 / seed_exp_7 | **0.6167** | 23.8 / 23.3 | 快 |
| expand_2 / entnolist_1 | 0.6167 | 44.1 / 43.9 | 快 |
| enton_1 | 0.6533 | 92.6 | 中间（不可归态） |

**同态内部完全一致**（慢态 base 三次都是 0.6200；快态 base 两次都是 0.5533），
**跨态漂移 6.67 pt**。

## 二、为什么这很重要

1. **6.67 pt 的漂移 >> 此前设定的 2 pt 噪声门槛**（300 题下 1 题 = 0.33 pt）。
   跨批次的绝对指标**完全不可比**——一个真实的 +5 pt 改进，可能被 −6.67 pt 的态漂移
   掩盖成负值；反之亦然。
2. **"必须同批次比较"这条纪律，此前只是经验；现在有了量化幅度**：
   跨批次绝对差值可达 **6.67 pt**，而批内相对差值稳定。
3. `meta.elapsed_s` 可作为态指示器（≥120 s 判慢态）。**后续所有对比必须记录它**。

## 三、疑似成因

最强嫌疑是**嵌入服务（ollama bge-m3）在冷/热路径下输出有微小差异**：
- 慢态 = 冷启动/独占（每次真算），快态 = 缓存命中或批量路径
- 向量末位差异 → 检索里大量"分数接近"的候选发生 tie-break 翻转
  → 少数题目的最终名次改变 → inject 判定翻转（300 题里约 40 题）

⚠️ 这**不是** `PYTHONHASHSEED` 造成的：显式设 seed=1 与 seed=7 结果完全相同
（都是 0.5533 / 0.6167），说明与哈希随机化无关。

## 四、历史结论的复核（重要）

**好消息：此前所有横向对比都在慢态内完成，相互可比**：

| 对比 | 慢态内 | 结论是否受影响 |
|---|---|---|
| 候选生成量消融（vol_*，9 轮） | ✅ 同批 | 不受影响 |
| 语义链接消融（link_*） | ✅ 同批 | 不受影响 |
| 阈值消融（expand_all / hm / high） | ✅ 慢态同批 | 不受影响 |
| CE 重排 A/B（ab_cross_encoder） | ✅ 单进程内 | 不受影响 |
| B4 天花板（完美扩展） | ✅ 单进程内 | 不受影响 |
| 实体扩展全量 A/B（base_1 vs expand_1） | ✅ 慢态同批 | 不受影响 |

**受影响的两处**：

1. **组件验证里的 `enton`（0.6533）与 `entnolist`（0.6167）** —— 分别处于中间态与快态，
   **不能与慢态 base（0.6200）直接相减**。"白名单挡掉多少收益"这一项**待同批次重测**。
2. **`positive_rank.json`（A 类 67 题划分）带批次依赖** —— 它是单次运行算出的
   `inject_pass=False` 集合，换态后集合本身会变。所有基于它的分析（实体识别目标集、
   通道拆解的 A 类子集）都继承这个不确定性。**结论方向不受影响**（A 类占失分近六成
   在任何态下都成立），但精确题数会变。

## 五、后续必须做的两件事

1. **所有评测报告落盘 `elapsed_s` 与态标记**，禁止跨态相减
2. **关键对比同批次跑**：base 与 treatment 必须在同一条命令链里连续执行
   （本项目的 `eval_repeat.py` 已是串行跑批，只需保证 base 也在同一批里）
3. 若要根治：定位嵌入路径的差异来源（加缓存开关 / 固定批量 /
   改用本地 onnx 嵌入），让绝对指标可跨批次引用
